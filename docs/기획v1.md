## 1. 문제 정의

> ** 문제 배경

GitLab의 신규 입사자, 부서 이동자가 같이 새로운 업무 배정을 받았을때에 업무를 익힐 수 있도록 온보딩 하는 RAG 서비스이다.

실제 GitLab 회사의 사내 문서를 활용하였다.
이 사내 문서는 MD형태로 버전별로 분기가 관리되면서 업로드 되는 특징이 있다

>** 문제 정의

신규 입사자

1. 뭘 먼저 봐야 할지 모른다 — 전사 공통 자료와 부서 자료가 섞여 있고, 우선순위 안내가 없다.
2. 내 직무에 맞는 체크리스트인지 확신이 없다 — 핸드북이 직무별로 명확히 분리돼 있지 않아 읽어야 할 범위를 스스로 판단해야 한다.
3. 용어·약어·조직 구조가 생소하다 — 사내 맥락을 전제한 문서라 신규 입사자 기준으로 풀어 쓰여 있지 않다.
4. 문서가 최신인지 믿을 수가 없다 — 핸드북이 자주 갱신되는데 버전·시점 정보가 본문에 안 드러난다.

부서 이동자

5. 뭘 "다시" 해야 하는지 구분이 안 된다 — 전사 온보딩은 이미 끝났는데, 새 자료가 처음부터 다시인지 직무 전환분만인지 불명확하다. (근거: `people-group/promotions-transfers.md:701` — 직무 전환 시 새 직무 온보딩 완료 요구)
6. 이전 부서 지식과 새 부서 지식이 어떻게 겹치는지 모른다 — 부서 간 공통·차이 항목이 문서상 매핑돼 있지 않다.
7. "이미 아는 척" 할 위험과 "모르는 척" 비효율 사이에서 헤맨다 — 체크리스트가 숙련도 구분 없이 동일하게 제공된다.

공통

8. 왜 이 항목이 필요한지(근거) 설명이 없다 — 체크리스트성 자료가 "할 일"만 나열하고, 사유·출처 연결이 약하다.


## 2. RAG가 필수적인 이유

9. 핸드북이 수시로 갱신된다 — 문서가 바뀔 때마다 그 내용이 지연 없이 답변에 반영되어야 한다. RAG는 검색 대상 문서만 갈아끼우면 바로 반영된다.
10. 답마다 근거(출처)를 보여줘야 한다 — 체크리스트 항목이 왜 필요한지 문서 경로·섹션까지 추적할 수 있어야 한다(고통 포인트 8번과 직결). RAG는 검색된 chunk를 그대로 인용할 수 있어 추적 가능성이 확보된다.
11. 환각(지어내기) 억제 — RAG는 검색으로 넘어온 문서 범위 안에서만 답하도록 강제할 수 있어, 모르는 걸 그럴듯하게 지어낼 위험을 줄인다.
12. 데이터 규모와 비용 — 실측 기준 34개 핵심 부서·4,612개 md 정도 분량이라 학습 기반 접근에 쓸 데이터 자체가 부족하다. RAG는 임베딩 재계산 정도로 대응할 수 있다.
13. 질문마다 다른 조합이 필요하다 — 신규 입사자/부서 이동자, 직무·부서에 따라 꺼내야 할 문서 조합이 달라진다(고통 포인트 1·2·5·6번). RAG는 질문마다 다른 문서 집합을 검색해 대응할 수 있다.
14. 버전·출처 추적 — 문서 경로 + 커밋 SHA까지 남기려는 설계(최소 DB 기준)는 검색 결과에 메타데이터를 붙이는 RAG 구조에서만 자연스럽게 된다.

### PoC 공통 기준 — 네 도메인이 지킬 최소 단위

> 도메인마다 RAG 구조는 자유롭게 고르되, **나중에 합칠 수 있도록** 아래만 맞춘다.

| 항목 | 최소 기준 |
|---|---|
| 코퍼스 | 자기 도메인 핸드북 폴더(`docs/handbook/content/handbook/<도메인>/`)의 영어 원문. 문서마다 경로를 기록한다(커밋 SHA는 스냅샷 `0ab0299` 고정) |
| 최소 DB | 공용 참조 테이블 스키마 하나: `doc_id, domain, source_path, commit_sha, heading_path, chunk_text, embedding`. 컬럼만 합의하고 구현은 도메인별로 한다 |
| RAG 구조 기록 | 청킹 · 임베딩 · 검색 · 리랭크 선택과 **"왜 이 도메인에 최적인가"**를 4절 표에 남긴다 |
| 출력 | 체크리스트 공통 필드 `item, reason, source(path#heading), domain`. 항목 내용은 도메인마다 다르다 |
| 평가 | 영어 질문 + **사람이 표시한** 정답 문서·섹션(AI로 지어내지 않는다 — AGENTS.md 5절). 지표 Recall@k·Hit@k(k=1,3,5,10). 차이 0.03 미만이면 같다고 본다 |
| 산출물 | 도메인 PoC = 이슈 1개 · PR 1개 · 기준선 수치 1개 + **그 도메인 작업 기록 문서**(AGENTS.md 8절 — 코드만으로 끝나지 않는다) |
