# 개발환경 셋팅 가이드

이 저장소는 Python 의존성과 가상환경을 **uv** 하나로 관리하고, git 훅은 **lefthook**으로 돌린다.
처음 받은 사람은 1~2절만 따라 하면 바로 작업할 수 있다.

> 핵심 규칙 3개
> 1. `pip install`을 쓰지 않는다. 패키지는 **`uv add`** 로 추가한다.
> 2. 명령은 가상환경을 켜지 않고 **`uv run <명령>`** 으로 실행한다.
> 3. `pyproject.toml`이 바뀌면 **`uv.lock`도 같이 커밋**한다.

---

## 1. 도구 설치 (장비당 1회)

| 도구 | 용도 | macOS | Windows |
|---|---|---|---|
| uv (0.12.5 이상) | Python 설치·가상환경·패키지 | `brew install uv` | `powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 \| iex"` |
| lefthook | git 훅 (커밋·push 전 검사) | `brew install lefthook` | `scoop install lefthook` |
| Git (+ Git Bash) | 버전 관리 · 훅 스크립트 실행 | 기본 설치됨 | [git-scm.com](https://git-scm.com) — 훅 스크립트가 `bash`로 돌아서 Git Bash가 필요하다 |
| GitHub CLI (선택) | PR 생성·확인 | `brew install gh` | `winget install GitHub.cli` |

Python은 따로 설치하지 않아도 된다. uv가 `.python-version`(3.12)을 읽고 알아서 받는다.

```bash
uv --version        # 0.12.5 이상인지 확인 (낮으면: uv self update)
lefthook version
```

## 2. 저장소 받은 직후 (저장소당 1회)

```bash
git clone <repo-url>
cd LG_CNS_RAG_main

uv sync             # .venv 생성 + Python 3.12 + uv.lock 그대로 설치
lefthook install    # git 훅 설치 — 안 하면 검사 없이 커밋·push된다
cp .env.example .env   # API 키는 .env에만 적는다 (커밋 금지)
```

잘 됐는지 확인:

```bash
uv run pytest       # 1 passed
uv run ruff check . # All checks passed!
```

## 3. 매일 쓰는 명령

| 하고 싶은 것 | 명령 |
|---|---|
| main 최신 반영 후 의존성 맞추기 | `git pull && uv sync` |
| 테스트 | `uv run pytest` |
| 린트 (자동 수정) | `uv run ruff check --fix .` |
| 포맷 | `uv run ruff format .` |
| 스크립트 실행 | `uv run python path/to/script.py` |
| .env를 읽어서 실행 | `uv run --env-file .env python path/to/script.py` |

`git pull` 뒤에는 습관적으로 `uv sync`를 한 번 친다. 팀원이 패키지를 추가했으면 이때 설치된다.

## 4. 패키지 추가·제거

```bash
uv add openai                  # 런타임 의존성 → pyproject.toml + uv.lock 둘 다 바뀜
uv add --dev ipykernel         # 개발용 (테스트·노트북 등)
uv add --group eval ragas      # 용도별 그룹 (평가 도구처럼 서비스엔 안 들어가는 것)
uv remove openai               # 제거
uv lock --upgrade-package openai   # 특정 패키지만 최신으로
```

- 패키지 추가는 **그것만 하는 PR**(`chore/add-xxx`)이나 그 패키지를 처음 쓰는 기능 PR에 넣는다.
- PR에 `pyproject.toml`과 `uv.lock`이 **둘 다** 들어 있어야 한다. CI가 `uv sync --locked`로 둘이 어긋나면 실패시킨다.

### RAG 스택 후보 (예시, 아직 확정 아님)

옛 주제 `docs/기획.md` 4절(참고 레포 기준) 스택을 그대로 쓴다면 대략 이런 패키지가 들어간다. **팀에서 스택을 확정한 뒤** 추가한다.

| 역할 | 패키지 예시 |
|---|---|
| LLM·임베딩 API | `openai` (+ 임베더 제공사 SDK) |
| DB·벡터 검색 | `psycopg[binary]`, `pgvector`, `sqlalchemy` |
| 키워드 검색 (BM25) | `rank-bm25` |
| API 서버 | `fastapi`, `uvicorn[standard]` |
| 설정 (.env 읽기) | `pydantic-settings` |
| 평가 | `ragas` (→ `--group eval`) |

## 5. 노트북으로 실험할 때 (임베더·청킹 비교 등)

```bash
uv add --dev ipykernel   # 처음 한 번 (이미 있으면 생략)
```

- **VS Code**: 노트북 오른쪽 위 커널 선택 → `.venv/bin/python`(Windows: `.venv\Scripts\python.exe`)
- **Jupyter Lab**: `uv run --with jupyter jupyter lab` (jupyter 자체는 프로젝트에 추가하지 않고 그때만 씀)

실험 결과(점수)는 노트북 출력에만 두지 말고 PR 본문이나 `docs/`에 before/after로 남긴다 — `docs/기획v1.md` 6절에 들어갈 재료다.

## 6. 비밀값 (.env)

- 실제 키는 `.env`에만. `.env.example`에는 **키 이름만** 적고, 새 키를 쓰게 되면 여기에 이름을 추가한다.
- lefthook이 `.env` 파일과 개인키가 커밋되려 하면 막는다. 그래도 실수로 올렸다면 **키를 즉시 폐기(rotate)** 하고 팀에 알린다.

## 7. 데이터·인덱스 파일

원본 데이터와 벡터 인덱스는 git에 넣지 않는다 (`.gitignore`: `data/raw/`, `data/processed/`, `vectorstore/`, `chroma_db/`, `*.faiss`, `*.index`).
대신 **다시 만드는 스크립트**를 커밋한다. 1MB 넘는 파일은 lefthook이 커밋을 막는다.

## 8. 문제 해결

| 증상 | 원인 / 해결 |
|---|---|
| uv `required-version` 불일치 오류 | uv가 오래됨 → `uv self update` (brew로 깔았으면 `brew upgrade uv`) |
| CI에서 `The lockfile at uv.lock needs to be updated` | `pyproject.toml`만 커밋하고 `uv.lock`을 빠뜨림 → `uv lock` 후 `uv.lock` 커밋 |
| `uv.lock` 머지 충돌 | 충돌을 손으로 고치지 않는다. main 쪽 `uv.lock`을 받고(`git checkout --theirs uv.lock` 등) `uv lock`을 다시 돌린 뒤 커밋 |
| 커밋 시 `ruff` 훅 실패 | 대부분 자동 수정·재stage된다. 남은 오류만 손으로 고치고 다시 커밋 |
| 첫 push가 "main 직접 push 금지"로 막힘 | 정상. 브랜치를 만들어 push한다. 저장소 최초 부트스트랩 1회만 `LEFTHOOK=0 git push` |
| Windows에서 훅이 `bash: command not found` | Git Bash가 PATH에 없음 → Git for Windows 설치 후 Git Bash에서 작업 |
| VS Code가 패키지를 못 찾음 (빨간 밑줄) | 인터프리터를 `.venv`로 선택 (`Cmd/Ctrl+Shift+P` → Python: Select Interpreter) |
