# 케이스북(Recall Casebook. for Engineer) 구현 계획 — D4 집중

> 근거: DEC-067(방향)·DEC-068(사용자 결정 2026-10-16·17 — 구분은 DEC-068 Status). 서버·데이터·스키마는 바꾸지 않는다(10/17 동결, DEC-059 ⑤). `frontend/`만 바꾼다.

## 0. 한 줄
기존 검색(`api.search`)·카드 타입(`Card`)·묶기(`api.draft`) 위에 영어 UI·현대 CI 색의 **케이스북 화면(`#casebook`)**을 새로 얹는다. 기존 한국어 화면(`#search`·`#8d`·`#showroom`)은 지우지 않는다(DEC-067 ④).

## 1. 화면 (3단)
| 칸 | 내용 |
|---|---|
| 왼쪽 선례 체크 목록 | 검색 결과(현대·기아 최대 5건 + 다른 회사 10건). 체크하면 근거로 쌓임 |
| 가운데 쌓이는 상세 | 체크한 순서대로: 결함·결과·시정(말한 주체·데이터셋·스냅샷), **원인 원문(말한 주체·573 파일·`pdf_sha256`·제출일·글 정리 방식 — 접지 않고 항상)**, 확인 항목(생산 기간·공급사, 각각 출처), 연결된 NHTSA 결함 조사(번호·말한 주체·개시/종결일·요약 원문, PRD FR-8) |
| 오른쪽 | 선례별 메모 + 원인 묶기(LLM 보조, 문장을 쓰지 않음) |

## 2. 구조로 지키는 것
- 판정·원인 추정 필드·문구 없음(`principles.test.tsx`가 `casebook/` 소스도 훑는다). 같다·다르다·해당한다를 표시하지 않고 자사 원인을 제안하지 않는다.
- 원인 원문 한 글자도 바꾸지 않는다(`highlight`는 검증된 구간만 감싼다). 원인 칸이 없으면 상태 문구만 보인다.
- **공급사**는 응답에 573 판본 출처 필드가 없으므로, 원인 원문 출처(`cause.source`)나 생산 기간 출처가 있어 **같은 판본임을 확인할 수 있을 때만** 그 출처와 함께 보이고, 확인할 수 없으면 숨긴다(DEC-067 결정 ⑧, `casebook/sources.ts`).
- **메모**는 서버·LLM에 보내지 않는다. 저장 키는 "사건 이름(인코딩) + 리콜 번호"이고 사건 이름이 없으면 저장하지 않는다(탭 메모리에만, 새로고침·탭 닫기 전 경고). 사건 이름을 바꿔도(`|` 포함) 다른 사건의 메모가 섞이지 않고, 이름 없이 쓴 메모를 이미 메모가 있는 이름으로 확정하면 양쪽을 이어 붙인다. 저장이 실패하면 "저장됨" 대신 경고하고(실패한 메모 집합이 빌 때만 복귀), 전체 지우기가 실패하면 화면을 비우지 않고, 한 칸을 모두 지웠는데 저장소 삭제가 실패해도 화면 값을 되돌린다(`casebook/notes.ts`).
- 묶기는 누르기 전에는 호출하지 않는다. 보내는 선례는 **원인 글이 있는 것만 고른 뒤 앞 6건**이다(`sources.ts` `groupCandidates`). 공개 서버에는 `/draft`가 배포되지 않아 404이면 "Grouping is not available on this server."로 안내한다. 체크한 선례가 바뀌면 이전 묶음을 걷어 낸다. 확인 질문은 공개 서버에 `/draft`가 없어 `/draft` 응답을 쓰지 않고 PR-C에서 서버 고정 문장을 화면에 두었다(DEC-069 ②, 7절).

## 4. 정해진 것 (DEC-068)
- 내보내기는 `.docx` 유지. 다운로드 폴더의 `8D REPORT_양식.xls`(영문·한글 시트, 4D 칸 하나, "검증 방법" 칸 없음)는 `.xls`라 지금 코드로 채울 수 없고, 지원은 발표 뒤 과제다.
- D4 "검증 방법"은 8D 양식에 대응 칸이 없으므로 입력만 받고 내보내지 않는다.
- 묶기는 케이스북에 포함한다(서버 키가 있는 로컬 서버에서만 동작).
- 랜딩 영상·3D 시안 연출은 발표용 비공개 시안에만 두고 정식 앱은 도구 화면만 둔다.
- 팀 공유는 일단 하지 않고 혼자 진행한다(팀 합의는 닫지 않음, DEC-064 ⑥).

## 6. 검증
`cd frontend && npm ci && npm run lint && npm run build && npm test`. 실제 브라우저(헤드리스 Chrome)에서 공개 API로 검색 → 체크 → 사건 이름 → 메모 저장(localStorage 키) → 묶기 404 안내 → 390px 폭을 확인했다. 묶기 성공 경로는 `/draft` 응답을 가짜로 끼워 넣어 렌더(묶음·말한 주체·출처 파일·sha256·버린 인용 수)와 체크 변경 시 초기화만 확인했고, 실제 LLM 호출은 서버 키가 있는 로컬 서버(`DRAFT_ENABLED=1`)가 필요해 확인하지 못했다.

## 7. PR-C 구현 내용 (DEC-069)
- 화면 아래 전체 폭 구역 "D4 · Your cause analysis"(`D4Panel.tsx`): 왼쪽 **확인 질문**(도구가 만든 고정 문장, 서버 `QUESTIONS["d4"]`와 글자까지 같음 — `questions.test.ts`가 서버 파일과 대조), 오른쪽 **Escape Cause·Root Cause·Verification method** 입력 칸(서비스는 채우지 않음, 메모와 같은 저장 장치).
- 출력: 올린 8D `.docx`의 D4 칸에 엔지니어 글만 덧붙인 새 파일(원본 불변, 브라우저 안에서만). Verification method·확인 질문은 내보내지 않는다. 부록(체크한 선례의 타사 원인 원문, DEC-064 ③ 형식)은 **기본 꺼짐**이고 체크박스를 켤 때만 8D 표 뒤에 붙는다. "Copy the D4 text"는 같은 평문을 복사한다.
- 확인 질문 선택(DEC-071, 사용자 결정 2026-10-17): 기본 문장은 코드 규칙, 추가 질문은 묶기 호출에서 LLM이 고정 풀 `QUESTION_POOL`(P1~P10)에서 **번호만** 최대 3개 고르고 화면은 풀의 문장을 "Picked by the model"로 보인다. 누르기 전·공개 서버·실패 때는 기본 문장만(폴백). 서버 `picked_questions`·화면 `pickedQuestions`·풀 글자 일치 시험.
- SUBJECT: 양식의 SUBJECT 칸과 복사문에는 검색 문장을 넣지 않는다(칸은 그대로). 안내는 부록이 실제로 표 뒤에 놓였는지 patchDocx 결과 그대로 말한다. 사건 이름이 없으면 D4 글은 탭에만 있어 새 검색·사건 전환 확인창이 "Notes and D4 text"로 알린다. D4 구역에도 저장 상태·공용 PC 안내·삭제 실패 메시지를 보인다. patchDocx에 넘기는 내용은 `docxContent`(SUBJECT 비움)가 정해 시험이 이 연결을 지킨다.
- 시험: `d4Doc.test.tsx`(D4 글·검증 방법 제외·부록 opt-in과 출처 줄·합성 `.docx`에 실제로 넣기·저장 키·화면 문구·SUBJECT 비움·표 없는 파일·이스케이프·저장 안 된 글 판정), `questions.test.ts`. 확인하지 못한 것: 실제 고객사 양식·Word로 열기·`.xls`.
