# 회사명 대응표 확인 안내

> 대상: 이승노 님(D 파트). 코드를 몰라도 엑셀·구글 시트로 할 수 있는 확인 작업입니다.
> 만든 곳: PR #29 · 결정 기록: DEC-033 · 이슈 #24 A파트 "회사명 대응표를 `maker` 칸에 반영"

## 1. 왜 필요한가

리콜 신고서에는 같은 회사가 여러 이름으로 적혀 있습니다. 예를 들면 `FORD MOTOR COMPANY`와 `Ford Motor Company`, `GENERAL MOTORS CORP.`와 `General Motors LLC`입니다. 이대로 두면 사용자가 "GM의 선례"를 찾을 때 일부만 보입니다. 그래서 이름을 정리한 표를 만들었고, 사람이 맞는지 확인해야 합니다.

## 2. 파일 두 개

| 파일 | 역할 |
|---|---|
| `scripts/defect_precedent/maker_aliases_draft.csv` | **초안.** 스크립트가 만든 파일입니다. 이 파일은 고치지 마세요 (스크립트를 다시 돌리면 덮어써집니다) |
| `scripts/defect_precedent/maker_aliases.csv` | **확인본.** 초안을 복사해서 이 이름으로 저장하고, 여기에서 고칩니다. 스크립트는 이 파일을 건드리지 않습니다 |

엑셀에서 열 때 한글이 깨지면 "UTF-8"로 열기를 선택하세요.

## 3. 칸

| 칸 | 뜻 |
|---|---|
| `raw_maker` | 신고서에 적힌 이름 그대로 (고치지 않습니다) |
| `maker` | 정리한 이름. 대소문자·쉼표·Inc/Incorporated 같은 표기 차이와 **법인 형태 차이(Corp ↔ LLC)를 한 이름으로 통일**했습니다. 화면에 쓰일 이름이라 **철자·쉼표·마침표도 맞아야 합니다** |
| `maker_group` | **"같은 회사의 선례"로 묶어 볼 단위 = 같은 그룹이면서 같은 브랜드를 쓰는 회사들.** 미국 법인과 본사(Hyundai Motor America ↔ Hyundai Motor Company), 이름이 바뀐 회사(Chrysler → FCA → Stellantis)를 한 묶음으로 봅니다. 그룹 소속·개명은 **공개 문서로 확인한 것만** 묶고, 다른 브랜드·소유주가 바뀐 브랜드·그룹 밖 유통사(예: Gulf States Toyota)·확인하지 못한 곳은 묶지 않습니다. 모든 줄에 값이 있고, 묶을 곳이 없으면 `maker`와 같습니다 |
| `count` | 그 이름으로 신고된 리콜 건수. 많은 순서로 정렬돼 있습니다 |
| `maker_basis` | `maker`를 어떻게 정했나: 원문(그대로) · 표기 통일 · 법인 형태 통일 |
| `group_basis` | `maker_group`을 어떻게 정했나: **없음**(묶을 이름 없음) · **자동**(이름의 핵심 단어가 같음) · **초안**(이름 목록으로 직접 지정한 출처 표시일 뿐이고, 확인 여부는 `review` 칸으로 판단합니다 — 확인을 마친 줄에도 `초안`이 남을 수 있습니다) |
| `review` | **확인 상태.** `확인 필요`(검토 전) · `확인 완료` · `보류`(판단 못 함) · 빈칸(볼 필요 없음) |
| `review_required` | **고치지 마세요.** 스크립트가 쓰는 칸으로, 검토가 필요했던 줄에는 `필요`라고 적혀 있습니다. 이 줄은 `review`가 정확히 `확인 완료`여야 통과합니다 (`확인완료`처럼 띄어쓰기를 빼거나 칸을 비우면 "아직 확인 안 함"으로 처리되고, 알 수 없는 값은 오류로 멈춥니다) |
| `review_note` | **무엇을 확인할지**가 미리 적혀 있습니다. 확인한 내용이나 메모는 그 뒤에 이어서 적어 주세요 |

## 4. 이미 정해진 규칙 (팀 결정)

1. **법인 형태만 다르면 한 회사**로 봅니다. (`GENERAL MOTORS CORP.` = `General Motors LLC`)
2. **미국 법인과 본사는 `maker`는 따로, `maker_group`은 같게** 둡니다. (`Hyundai Motor America`와 `Hyundai Motor Company`는 다른 `maker`, 같은 `maker_group`)
3. **이름이 바뀐 회사는 `maker`를 새 이름으로 덮어쓰지 않고 `maker_group`으로만 잇습니다.** `maker`는 표기·법인 형태만 통일하고, 신고 당시 원문은 `raw_maker`에 그대로 남습니다. (Chrysler 계열은 `maker`가 6가지 이름으로 남고 `maker_group`이 하나)

## 5. 해 주실 일

### ① `review = 확인 필요`인 31줄 (우선)
`review_note`에 적힌 것을 확인하세요.
- **`maker_group:` 이 적힌 줄** (Chrysler 계열·Kia·Toyota·Volkswagen 등 초안 21줄, 핵심 단어가 하나뿐인 자동 4줄, 고객사 자동 4줄): 그 묶음이 맞는지 봅니다. 틀렸으면 `maker_group`을 고칩니다.
  - 예: `DAIMLERCHRYSLER CORPORATION`과 `CHRYSLER LLC`를 Chrysler와 같은 묶음으로 봐도 되는가
  - 예: `Toyota Motor Engineering & Manufacturing`(미국 생산 법인)을 Toyota로 묶어도 되는가
  - 예: `Hyundai Motor America`와 `Hyundai Motor Company`(고객사 현대·기아·제네시스는 자동으로 묶인 줄도 확인 대상입니다)를 한 묶음으로 봐도 되는가
- **`maker:` 가 적힌 줄** (2줄, Piaggio): 대표 이름의 철자를 봅니다. 신고서 원문에 `Americas. Inc.`(마침표)와 `Americas, Inc.`(쉼표)가 같이 있어서 쉼표 쪽을 대표로 골랐습니다. 이 경우처럼 `maker` 철자가 틀렸으면 고칩니다.

### ② 확인한 줄은 `review`를 반드시 바꿉니다
- 맞으면 → `확인 완료` (**띄어쓰기까지 정확히**. `확인완료`처럼 쓰면 확인한 것으로 인정되지 않습니다)
- 확신이 없으면 → `보류`, `review_note`에 이유를 적습니다. 지우거나 추측해서 채우지 마세요. 확신 없는 묶음을 넣는 것보다 묶지 않는 쪽이 안전합니다 (사용자가 서류에 쓰는 정보입니다)
- **줄을 지우거나 새로 넣지 마세요.** 초안(`maker_aliases_draft.csv`)과 줄 목록을 대조하기 때문에, 줄이 사라지거나 늘어나면 카드에 적용하는 단계가 오류로 멈춥니다. 필요 없는 줄도 지우지 말고 `review_note`에 이유를 적어 주세요.
- **`확인 필요`나 `보류`가 하나라도 남아 있으면 카드에 적용하지 않습니다.** 그래서 "맞아서 그대로 둔 줄"도 `확인 완료`로 바꿔야 확인했다는 기록이 남습니다.

### ③ 큰 회사에서 빠진 연결 찾기
`count`가 큰 위쪽 **100줄 정도**만 훑어보세요. 1건짜리 회사 약 2,000곳은 확인해도 효과가 거의 없습니다. 같은 계열인데 `maker_group`이 다른 이름으로 남아 있으면 `maker_group`을 같은 값으로 맞추고, 그 줄은 `review = 확인 완료`와 이유를 `review_note`에 적어 주세요.
- 이 표는 이름이 비슷한 것만 자동으로 묶습니다. 이름이 전혀 다른 계열사나 합병·인수 관계(예: 브랜드와 모회사)는 **자동으로 알 수 없어서 사람이 채워야 합니다.**

## 6. 돌려주는 방법

- 고친 `maker_aliases.csv`를 박예원 님께 전달해 주세요.
- 받으면 박예원 님이 다음을 진행합니다: `확인 필요`·`보류`가 남아 있는지 검사 → 카드(`recalls.jsonl`)의 `maker`·`maker_group`에 반영 → 새 기준 파일 만들기 → 점수가 그대로인지 확인(재현). 이 작업이 끝나기 전까지는 기존 기준 점수 0.510에 영향이 없습니다.

## 7. 주의

- 이름 목록은 NHTSA 공개 리콜 파일의 `MFGNAME`입니다. 기업 정보를 외부에서 가져온 것이 아니라 **이 파일에 적힌 이름만** 다룹니다.
- `초안` 값은 확인 전입니다. 확정 전에는 화면·답변에 "같은 회사"라고 단정해서 쓰지 않습니다.
