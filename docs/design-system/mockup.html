선례 검색 화면 설계

3D 쇼룸(PR #60) 옆에 붙을 검색 전용 화면의 디자인 토큰, 컴포넌트, 화면 목업입니다. 목업의 영어 원문과 번호는 공개 API(https://lg-cns-rag.vercel.app)가 2026-10-13에 돌려준 응답을 그대로 그렸고, 손으로 옮겨 적지 않았습니다. 이 문서가 확정되면 구현 PR(검색 화면 + API 연동)의 기준이 됩니다.

화면이 지키는 원칙

AGENTS.md 2절 서비스 원칙이 화면에 주는 제약입니다. 오른쪽 태그는 이 원칙을 지키는 컴포넌트입니다.

판정하지 않는다

"리콜 대상", "원인은 ~", "해당 / 해당 없음" 같은 결론 문구와 그런 인상을 주는 색(빨강·초록·경고 주황)을 쓰지 않습니다. 확인 항목도 같다/다르다를 표시하지 않고 근거 원문만 나란히 놓습니다.

원인 상태 배지 · 확인 항목 · 강조색 남색
원문은 감싸기만 한다

결함·결과·시정·원인·조사 요약은 서버가 준 글 그대로 보여 줍니다. 번역·요약·대소문자 정리를 하지 않고, 꼬리표는 글자를 바꾸지 않는 밑줄로만 표시합니다. 목록의 첫 1~2줄은 자르기만 합니다.

원문 블록 · 꼬리표 밑줄 · 목록 항목
말한 주체와 출처를 붙인다

원문 블록마다 머리줄에 말한 주체와 번호(리콜 번호·573 캠페인·조사 번호)를 항상 보이고, 파일·sha256·text_basis·제출일은 "출처 자세히"로 펼칩니다.

바이라인 · 출처 자세히 · 출처 꼬리
없으면 없다고, 이유와 함께

원인 원문이 없는 카드는 빈칸 대신 상태 문구(수집 범위 밖, 판독 실패 등)를 보여 줍니다. stated_unknown을 "원인을 모름이 확인됨"이라고 쓰지 않습니다.

컴포넌트

검색 화면에서 그대로 쓰는 모양입니다. 원인 상태 중 공개 API 응답에 없던 것은 합성 표시를 붙여 형식만 보입니다.

상단 바 · 화면 전환

탭 두 개(선례 검색 기본 / 3D 쇼룸(데모))는 주소 해시(#search·#showroom)로 기억합니다. 오른쪽 점은 서버 판본(/health) — 받는 중이면 빈 점.

검색 입력

영어 질문만 받습니다(서버 규칙). 한글만 입력하면 보내기 전에 아래 안내를 보입니다. 1~4000자.

목록 항목 · 일반 / 선택

질문 의 실제 응답입니다. 왼쪽 목록을 누르면 오른쪽 상세가 바뀝니다. 14E073000은 원인 원문이 "The cause is under investigation"인데 상태는 filled입니다 — 상태 이름만 보고 판단하지 않도록 원문과 꼬리표를 함께 보여 주는 이유입니다(#83).

목업 · 처음 화면 · 로딩 · 오류

열린 질문 — 다음 검토에서 정할 것

1. 쇼룸에서 부품 분류를 누르면 검색으로 이어 줄까?

제안: 쇼룸 패널에 "이 분류로 선례 검색" 버튼을 두고 분류 영어 이름(예: air bag)을 질문 칸에 채워 검색 화면으로 넘깁니다. 자동 검색은 하지 않고 사용자가 고쳐서 보내게 합니다.

2. 예시 질문 문구

제안: 아래 네 개. 시험지 질문과 겹치지 않는지 구현 때 기계로 확인합니다.

3. 상세 패널 순서

제안: 머리(순위·번호·회사·접수일·부품) → 결함·결과·시정 원문 → Part 573 원인 → NHTSA 조사 → 확인 항목 → 출처 꼬리. 확인 항목을 맨 위로 올리는 안도 있습니다(근거를 먼저 보고 원문으로 내려감).

4. 원문 글꼴을 세리프로 할까?

제안: 원문(1차 자료)은 Source Serif 4, 화면 글은 Pretendard로 구별합니다. 쇼룸 카드 원문도 같은 토큰으로 맞출지 함께 정합니다.

5. 화면에 띄울 판본 정보

제안: 상단 바에 스냅샷 날짜와 카드 수, 결과 아래 출처 꼬리에 build_id·bundle_sha256 앞 12자(전체는 마우스를 올리면). 발표 화면에서는 꼬리를 접어 둘 수 있게.

6. 고객사 선례가 없을 때

제안: 구역 제목은 남기고 "검색 상위 100건 안에 현대·기아 리콜이 없습니다"라고 적습니다. 구역을 숨기면 고객사 선례를 찾아봤다는 사실이 사라집니다.
