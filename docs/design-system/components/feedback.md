# 로딩 · 오류 · 빈 결과

| 시간 | 화면 |
|---|---|
| 0~3초 | 목록 자리에 뼈대 상자 4개(반짝임, `prefers-reduced-motion`이면 정지). 상세 자리는 비움 |
| 3초 뒤 | 위에 `--accent-soft` 안내 "서버가 깨어나는 중일 수 있습니다. 첫 요청은 13~16초쯤 걸립니다." (실측: 새 배포 직후 첫 요청 12.8~16.1초, 이후 0.2~0.5초 — `docs/guides/배포_Vercel.md` 3-1절) |

## 오류

### 이전 설계 5종 — 삭제된 한국어 검색 화면(DEC-075) 시점

현재 케이스북(영어 UI)의 오류 문구는 `frontend/src/casebook/errors.ts`가 정본이다. 아래 5행은 삭제된 한국어 화면을 위해 정한 안이다.

흰 바탕, `--line-strong` 테두리, **왼쪽 4px `--ink-2` 띠**(빨강을 쓰지 않음). 제목(13px 굵게) + 설명 + 필요하면 "다시 시도" 버튼.

| 종류 | 언제 | 제목 | 설명 |
|---|---|---|---|
| 입력 오류(422) | 서버가 질문을 거부 | 질문을 다시 확인해 주세요 (422) | 서버 메시지 `detail[0].msg`를 그대로(앞의 "Value error, "만 뗌) — 예: "영어 단어가 들어간 질문이 필요합니다" |
| 연결 실패 | fetch가 TypeError | 서버에 연결하지 못했습니다 | "네트워크 또는 허용 주소(CORS) 설정을 확인해 주세요. API 주소: {API_BASE}" — 브라우저에서는 두 원인을 구별할 수 없어 둘 다 적는다. [다시 시도] |
| 시간 초과 | 60초 | 응답이 60초 안에 오지 않았습니다 | "서버가 깨어나는 중일 수 있습니다. 한 번 더 보내 주세요." [다시 시도] |
| 형식 다름 | 응답 모양이 예상과 다름 | 응답 형식이 예상과 다릅니다 | "화면이 아는 응답 모양과 달라 결과를 그리지 않았습니다. build_id {…}" |
| (서버 오류 5xx) | 500 등 | 서버 오류가 났습니다 ({code}) | [다시 시도] |

### 현재 케이스북 — 호출 상한(429)

| 종류 | 언제 | 제목 | 설명 |
|---|---|---|---|
| 호출 상한(429) | 서버가 IP별 호출 상한을 넘겼다고 응답(DEC-057) | Too many requests. | "Too many requests."만 알림에 둔다(남은 초는 따로 센다) · `Retry-After` 초(머리글이 없거나 숫자가 아니면 60초) 동안 "{n}s left"를 보이고 [Retry (n)]·검색 단추를 비활성 · 다 기다리면 "You can search again." 안내 후 [Retry] 활성 |

호출 상한(429) 행은 옛 한국어 검색 화면 시점이 아니라 **현재 케이스북 화면(영어 UI)이 구현한 동작과 문구**(`frontend/src/casebook/errors.ts`·`SearchError.tsx`·`useCountdown.ts`)를 적은 것이다. 한국어 화면에 쓰려던 안은 "잠시 뒤에 다시 시도해 주세요(429)"였고(이슈 #63) 그 화면은 DEC-075로 지워졌다. 다시 누를수록 상한에 더 걸리므로 비활성 구간을 두는 것이 이 행의 목적이다.

오류가 나도 입력한 질문은 칸에 그대로 둔다.
