# 화면이 지키는 원칙

AGENTS.md 2절 서비스 원칙이 화면에 주는 제약이다. 엔지니어는 이 화면이 보여 준 선례와 원인 문장을 리콜 범위·보고 판단의 근거로 쓴다. 그래서 아래는 문구가 아니라 화면 구조로 지킨다.

| 원칙 | 화면에서 뜻하는 것 | 지키는 컴포넌트 |
|---|---|---|
| **판정하지 않는다** | "리콜 대상", "원인은 ~", "해당 / 해당 없음" 같은 결론 문구를 쓰지 않는다. 판정 인상을 주는 색(빨강·초록·경고 주황)을 쓰지 않는다. 확인 항목은 같다/다르다를 표시하지 않고 근거 원문만 나란히 둔다 | [원인 상태 배지](components/cause.md) · [확인 항목](components/checklist.md) · 강조색 남색([colors](tokens/colors.md)) |
| **원문은 감싸기만 한다** | 결함·결과·시정·원인·조사 요약은 서버가 준 글 그대로. 번역·요약·대소문자 정리를 하지 않는다. 꼬리표는 글자를 바꾸지 않는 밑줄로만, 목록의 원문은 자르기만(…) | [원문 블록](components/precedent-detail.md) · [꼬리표](components/cause.md#꼬리표) · [목록 항목](components/result-list.md) |
| **말한 주체와 출처를 붙인다** | 원문 블록마다 말한 주체와 번호(리콜 번호·573 캠페인·조사 번호)를 항상 보이고, 파일·sha256·text_basis·제출일은 "출처 자세히"로 펼친다 | [바이라인·출처 자세히](components/precedent-detail.md) · [출처 꼬리](components/precedent-detail.md#출처-꼬리) |
| **없으면 이유와 함께 알린다** | 원인 원문이 없는 카드는 빈칸 대신 [상태 문구](copy/cause-status.md)를 보인다. `stated_unknown`을 "원인을 모름이 확인됨"이라고 쓰지 않는다 | [원인 블록 9종](components/cause.md) |
| **추적할 수 있다** | 결과 아래에 build_id·묶음 sha256·스냅샷·모델·서버가 받은 질문을 남긴다 | [출처 꼬리](components/precedent-detail.md#출처-꼬리) · [상단 바 판본 점](components/app-bar.md) |

## 상태 이름만 보고 판단하지 않는다

상태 값은 분류 규칙의 결과일 뿐 원문의 뜻을 보장하지 않는다. 실제 응답 예: `14E073000`의 원인 원문은 "The cause is under investigation"인데 상태는 `filled`다(경계 문제는 #83). 그래서 원인 블록은 상태 배지와 함께 **원문과 꼬리표를 항상 같이** 보인다.

## 화면 코드에 대한 기계 검사 (구현 때)

- 판정 문구 정규식이 화면 소스·렌더 결과에 0건이어야 한다(`scripts/ci/pr_checks.py`의 principles 패턴과 같은 식).
- 원문 칸은 렌더 결과에 서버 원문이 그대로(HTML 이스케이프만) 들어 있어야 한다.
- 꼬리표 강조 조각을 이어 붙이면 언제나 원문과 같아야 한다([cause.md](components/cause.md#꼬리표)).
