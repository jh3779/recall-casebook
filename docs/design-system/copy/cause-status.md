# 원인 상태 문구 (잠정 — 이슈 #53에 올릴 안)

상태 값은 `server/api.py`의 원인 모델 그대로다(어느 상태가 언제 나오는지는 `server/rag/causes.py`). 문구는 사실만 말하고 원인을 단정하지 않는다. `{campaign}`·`{reason}`·`{status}`는 서버 값을 그대로 끼운다.

| 상태 값 | 단계 | 화면 문구 |
|---|---|---|
| `filled` | 원인 원문 있음 | Part 573 원인 칸 원문입니다. |
| `stated_unknown` | 미보고·조사 중 표현 | Part 573 원인 칸 원문입니다. 원인 서술 대신 미보고·조사 중 등의 표현으로 시작하는 글로 분류됐습니다(DEC-047). 원인을 모른다는 뜻으로 단정하지 않습니다. |
| `no_573_report` | 원인 원문 없음 | 접수일이 2014-08-20 이전이라 Part 573 원문 수집 범위 밖입니다. 원인 원문을 싣지 않습니다. |
| `report_unreadable` | 원인 원문 없음 | Part 573 보고서({campaign})를 읽지 못했습니다. 사유: {reason} |
| `report_status_unknown` | 원인 원문 없음 | Part 573 보고서({campaign})를 수집했는지 확인하지 못했습니다. |
| `version_unresolved` | 원인 원문 없음 | Part 573 보고서({campaign})의 판본이 여럿이고 최신판을 정하지 못해 원인 원문을 싣지 않습니다. |
| `cause_empty` | 원인 원문 없음 | Part 573 보고서({campaign})의 원인 칸이 비어 있습니다. |
| `cause_no_field` | 원인 원문 없음 | Part 573 보고서({campaign})에서 원인 칸을 찾지 못했습니다. |
| `verify_failed` | 원인 원문 없음 | 원인 원문이 글자 대조를 통과하지 못해 싣지 않습니다({campaign}). |
| (모르는 값) | 원인 원문 없음 | 원인 상태: {status} |

## 쓰지 않는 표현

- "원인 없음", "원인 불명 확인", "원인을 모름" — 서버가 확인한 것은 글이 있는가와 분류 규칙뿐이다.
- "원문에서 원인 서술을 찾지 못함" — 원인 칸이 없는 카드에는 "별도 573 원인 칸 없음"처럼 사실대로(#53 제안).
- 상태 값 영문 이름을 문구로 그대로 노출하지 않는다(모르는 값만 예외).

## `report_unreadable` 사유 값

서버 `reason`은 코드 그대로 보인다(예: `non_pdf_response`, `no_confirmable_date`). 한국어 풀이를 붙일지는 #53에서 정한다.
