# 실험 P5 — 사례가 적은 부품에서도 잘 찾는가 (사후 층화 분석, 2026-10-21)

> 발표 후 피드백 "사례가 적은 것들에 있어 잘 찾을 수 있는지에 대한 것"에 대한 답.
> **사후 층화 분석**이다 — 새 시험지·새 정답이 없고, 기존 749문항을 정답 리콜의 부품 희소성으로 나눠 다시 읽었다. 튜닝에 쓰지 않았고, 대리 평가·시점 평가 점수와 합치지 않는다(AGENTS.md 5-2).
> 재현: `uv run --with fastembed==0.9.0 python -m scripts.defect_precedent.rare_strata` (아래 8절). 사전 고정 규칙은 2절, 결과 JSON은 `data/processed/defect/rare_strata_20261021/`에 쓰며 커밋하지 않는다.

## 1. 한 줄 결론

**사례가 적은 부품이라서 더 못 찾는 경향은 보이지 않았다. 오히려 사례가 많은 부품(>250장)에서 가장 낮았다.** 다만 가장 드문 24문항에서는 절반(12/24)만 상위 10개 안에 들어서, 이 구간의 결론은 건수가 적어 약하다. 실패한 12문항에는 질문에 결함 내용이 거의 없는 것(2건)도, 결함 내용이 있는데도 놓친 것도 섞여 있다. **왜 그런지는 검증하지 않았다.**

## 2. 무엇을 어떻게 쟀나

| 재현 확인 | 전체 점수가 기준과 일치: BM25 0.510, RRF 0.542, 회사 이름 뺀 질문 0.483 / 0.531 (캐시 검증 통과, fastembed 0.9.0) |

| 구간(결과를 보기 전에 고정) | 드묾 ≤50장(150문항) / 중간 51~250장(415) / 흔함 >250장(184). 분포(건수)만 보고 정함 |
| 지표 | any@10 — 정답 중 하나라도 상위 10개에 든 비율(본 평가의 0.542와 같은 정의). 구간별 Wilson 95% 신뢰구간 |
| 판단 규칙 | 기준 폭 0.03 안이면 "같다"고 본다(AGENTS.md 5-3) |

## 3. 결과

`적중률 (맞힌 수/문항 수, 95% 신뢰구간)`

| 흔함 (>250장) | 184 | 0.451 (83/184, 0.38–0.52) | **0.429** (79/184, 0.36–0.50) | 0.446 (82/184) | 0.462 (85/184, 0.39–0.53) |
| 전체 | 749 | 0.510 | **0.542** | 0.483 | 0.531 |

가장 드문 구간(부품 라벨 카드 ≤10장, 24문항): RRF 12/24(0.50, 신뢰구간 0.31–0.69), BM25 14/24(0.58). 두 방식 모두 건수가 적어 우열을 말할 수 없다.

### 읽는 법
1. **드묾(≤50) 0.613 vs 흔함(>250) 0.429 — 차이 0.184.** 기준 폭(0.03)보다 훨씬 크고, 신뢰구간(0.53–0.69 대 0.36–0.50)이 겹치지 않는다. 드문 부품이 불리하지 않았다.
2. **흔함 구간에서만 합치기(RRF 0.429)가 단어 검색(0.451)보다 낮다**(−0.022, 기준 폭 0.03 안이라 "같다"로 본다 — 이유는 검증하지 않았다). 합치기의 이득(+0.032)은 드묾·중간 구간에서 나왔다(드묾 +0.040, 중간 +0.053).
3. **회사 이름을 뺀 질문에서도 같은 방향**이다(드묾 0.600 > 중간 0.537 > 흔함 0.462).

## 4. 관찰과 가설 (이유는 검증하지 않았다 ⚠)
**서버(와 이 스크립트)는 모든 질문을 똑같이 30,350장 전체와 비교한다**(`server/rag/search.py`, 부품 필터 없음 — DEC-045로 기각). 그래서 "같은 부품 라벨 카드가 적어 후보 공간이 작다"는 설명은 성립하지 않는다. 이 분석이 보여 준 것은 **희소 구간에서 BM25·RRF의 적중률이 높게 관찰됐다**는 상관뿐이다.
- **가설 ① 경쟁 카드**: 같은 라벨 안에서 정답과 비슷한 글을 가진 카드가 적어 상위 10개에 들기 쉬울 수 있다. 확인하지 않았다.
- **가설 ② 질문의 정보량**: 가장 드문 24문항 중 RRF 실패 12건의 질문 앞부분(170자)을 읽었다. 결함 내용이 거의 없는 것은 2건이다 — `EA97003` "THIS INVESTIGATION IS CLOSED."(`SEAT BELTS:INTEGRATED CHILD SEAT`), `EA02013` "THIS INVESTIGATION WAS OPENED AS PE02-031 … BASED ON TWO REPORTS."(`CHILD SEAT:BASE`). 반면 결함 내용이 있는데도 놓친 것이 있다 — 예: `PE20018`(RRF 순위 18, BM25 순위 4), `PE98032`(stop lamp switch), `PE96064`(harness release button), `PE86067`(brake failure), `PE07037`(rear drivetrain). 성공한 예(`EA09006` TRACTION CONTROL SYSTEM, `EA09016` AUTOMATIC TRANSMISSION)는 질문에 결함 내용이 들어 있다. **질문 전문을 읽거나 정량 분류한 것은 아니므로** 정보량이 실패의 이유라고 말할 수 없다.
- 따라서 이 분석은 "드문 부품에서 잘한다"가 아니라 **"드문 부품이라는 이유로 더 나빠지는 경향은 보이지 않았다"** 까지만 말한다.

## 5. 한계 (미리 적은 것 + 추가)
1. **희소성을 정답 카드의 라벨로 정했다.** 실제 사용자는 정답을 모르는 채 질문하므로 "질문 시점에 알 수 있는 희소성"이 아니다.
2. **대리 평가라는 한계가 그대로다.** 정답 리콜의 99.6%가 조사 시작 뒤에 접수돼, "과거 선례를 찾는가"를 재지 못한다. 이 분석은 그 한계를 풀지 못한다.
3. **구간이 좁을수록 신뢰구간이 넓다.** ≤10장 24문항은 ±약 0.19 — 결론이 아니라 관찰이다.
4. **부품 라벨 건수는 부품의 "사례 수"와 같지 않다.** 라벨이 세분화돼 있어 같은 종류의 부품이 여러 라벨로 흩어져 있을 수 있다. 상위 분류(대분류)로 묶으면 구간이 달라진다(미실시).
5. **사후 분석이다.** 구간 기준은 결과(Hit)를 보기 전에 정했다고 작성자가 기록했지만, 이 저장소의 이전 기록으로 독립 검증할 수 없다(스크립트와 문서가 같은 PR에 들어갔다). 분석 자체는 이미 있는 점수를 다시 읽은 것이라 새 성능 주장으로 쓰지 않는다.

## 8. 재현 방법과 사전 고정 기록

```bash
RETRIEVAL_CACHE=data/processed/defect/retrieval_cache \
  uv run --with fastembed==0.9.0 python -m scripts.defect_precedent.rare_strata
```

- 입력: `data/processed/defect/recalls.jsonl`·`eval.jsonl`(P4와 같은 build). 임베딩 캐시가 있으면 다시 계산하지 않는다.
- **실행 전에** `recalls.jsonl`·`eval.jsonl`의 sha256을 `baseline_2026-10-06_maker-aliases.json`과 대조해 다르면 멈춘다 — 입력이 다르면 "재현"이 아니라 "재평가"로 보고한다(AGENTS.md 5-1). **끝에** 전체 점수(BM25 0.510 / RRF 0.542 / 회사 이름 뺀 질문 0.483·0.531)를 기준과 대조해 출력하고, 입력 지문·모델·구간 경계·대조 결과를 `result.json`에 기록한다(같은 폴더에 다시 실행하면 덮어쓴다).
- 구간 기준(≤50장 / 51~250장 / >250장)은 결과(Hit)를 보기 전에 부품 라벨 카드 수 **분포만 보고** 정했고, 스크립트 상수(`BOUNDS`)로 고정돼 있다. 바꾸려면 새 사전 고정 기록이 필요하다.
