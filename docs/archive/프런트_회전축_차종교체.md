## 사용자 선택과 구현

사용자는 회전축 고정과 현대·기아 차종 교체를 요청했고, **팰리세이드·쏘렌토**, **실차에 가까운 3D 파일 확보 후 적용**을 선택했다. 외형을 본뜬 간소화 모델 제작은 선택하지 않았다.

회전축 고정은 구현했다. 차량 중앙 `(0, 0.8, 0)`을 중심으로 수직축을 따라 수평 회전한다. 팬과 상하 회전은 막고 확대·축소는 유지한다. 부품 선택으로 카메라가 이동하는 동안에도 회전 중심이 부품으로 따라가지 않는다. 초기 카메라 위치를 설정한 직후 OrbitControls도 갱신한다.

차종 교체는 **미완료**다. 현재 화면은 Silverado·Ram이며 기존 리콜·부품 대응표를 그대로 유지한다. 팰리세이드·쏘렌토 원본 파일을 확보한 뒤 재질·크기·좌표·부품 구성과 해당 차종의 리콜 범위를 확인해야 한다. 이름만 바꾸거나 기존 트럭 리콜을 새 차종에 붙이지 않았다.

## 파일 확보 조사

- [Kia Sorento — MattDoesBlender](https://sketchfab.com/3d-models/kia-sorento-47a0016ba8b842c780d79ded8fa0a891): CC BY 4.0, 288.3k 삼각형. 로그인 후 다운로드 패널에서 GLB 17MB·glTF 4MB를 확인했다. GLB 다운로드를 눌렀지만 브라우저 도구가 `Invalid InterceptionId`로 실패해 파일 경로를 받지 못했다. 이후 다운로드 기록 페이지는 브라우저 URL 정책으로 열 수 없었다. 다운로드·형상 적합성 검증은 완료했다고 보지 않는다.
- [Hyundai Palisade — flightmaster177](https://sketchfab.com/3d-models/hyundai-palisade-253b4ffad4374a5dba4ea903290a3792): CC BY-NC-SA 4.0, Scaniverse 스캔 모델. 완성된 차량 외관·부품 분리 품질을 확인하지 못해 채택하지 않았다.
- [Hyundai Palisade 2018 — pSergio](https://www.turbosquid.com/FullPreview/2013864): 정밀 외관 후보, 검색 결과에 FBX·OBJ와 266,836 폴리곤으로 소개됨. 상품 페이지는 기기 확인 화면에서 멈춰 현재 가격과 다운로드 조건을 직접 확인하지 못했다. 구매하지 않았다.

다음 입력은 다운로드 가능한 실제 GLB/FBX 파일 또는 모델 구매 예산이다. 원본과 출처·라이선스를 보관하고 실제 파일을 검사한 뒤 적용한다. 모델 바이너리는 기존 방침대로 gitignore 대상이다.

## 테스트 근거

사용자 동선: 부품 선택 → 투시 보기 → 외관 복귀 → 자동 회전, 어느 단계에서도 회전 중심과 축이 바뀌지 않는다.

1. RED: `npm test -- src/showroom/rotation.test.ts`에서 부품 선택 시 중심이 `[0, 0.8, 0]` 대신 `[1.8, 0.4, -0.7]`이 되는 기존 오류를 재현했다. 별도 애니메이션 테스트에는 생성자를 건너뛴 준비 오류가 있어, AGENTS.md 3-5에 따라 사용자 확인을 받고 생성자를 실행하도록 수정했다.
2. GREEN: 같은 파일 4개 통과. 실제 Showroom 생성자·애니메이션·OrbitControls를 사용하고 GPU·DOM만 대체한다. 부품 선택, 애니메이션 중간/끝, 처음 시점 복귀, 모션 줄이기, 팬·상하 회전 제한, 수평 자동 회전을 검사한다.
3. Node 24.21.0에서 `npm ci`, `npm run lint`, `npm run build`, `npm test`: 모두 통과. 전체 10개 파일·83개 테스트. 기존 500KB 청크 경고는 남는다.
4. `uv run ruff check .`, `uv run ruff format --check .`, `uv run pytest`: 통과. 114개 파일 포맷 정상, 498개 통과·16개 생략(DB 설정 없음), 기존 runpy 경고 1개.
5. Chrome에서 부품 선택·투시 표시를 확인했고 캡처된 경고·오류 로그는 0건이었다. 회전 중심 좌표·각도는 단위/통합 테스트에서 검사했다.

`coverage` 스크립트와 계측 도구가 없어 커버리지 비율은 측정하지 않았다. TDD 스킬의 체크포인트 커밋은 저장소의 ‘사용자 요청 때만 커밋’ 규칙에 따라 만들지 않았다. 실패·통과 근거는 이 문서에 남긴다. 커밋·push·배포는 미실행이다.
