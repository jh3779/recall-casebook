# 쇼룸 모델 표면 정리

> Silverado·Ram을 사용하던 단계의 기록이다. 현재 화면은 [코나·쏘렌토 외관 모델](../experiments/프런트_현대기아_모델.md)로 교체했고 새 모델의 원본 법선·텍스처·스킨을 유지한다. 아래 평활화 도구와 검사는 이전 모델 재현용으로 보존한다.

2026-10-13. 사용자 요청은 모델 면 다듬기이며, 추가 확인에서 **각진 면·거친 음영을 매끈하게 다듬기**를 선택했다. `feat/search-view`의 `5f258f1` 위 로컬 변경이다. 커밋·push·배포는 하지 않았다.

## 변경과 근거

원본은 유한요소 차량 모델을 단순화한 GLB다. Silverado에는 한 메시 안에서 같은 위치를 차지하는 중복 삼각형이 273,573개 있었고, Ram에는 메시 사이에도 겹친 면이 있었다. 기존 법선을 그대로 쓰면 겹친 면과 급격한 음영 변화가 차체에 얼룩처럼 드러날 수 있다.

`frontend/src/showroom/geometry.ts`가 모델을 읽을 때 다음 처리를 한다.

1. 면적이 0인 삼각형과 세 꼭짓점이 정확히 같은 중복 삼각형을 제거한다. 양면 재질이므로 순서만 뒤집힌 면도 하나만 남긴다.
2. 다른 메시의 중복은 부품 분류·재질 구분·변환 행렬이 모두 같을 때만 정리한다. 부품 선택 위치는 정리 전 모델로 계산한다.
3. Three.js `toCreasedNormals`로 45도보다 완만한 면 사이의 음영을 부드럽게 한다. 더 크게 꺾이는 모서리에는 분리된 법선을 유지한다. `mergeVertices`로 위치와 법선이 같은 정점을 다시 공유한다.
4. 차체 재질의 금속성·반사 거칠기를 조절해 작은 음영 변화가 과하게 번쩍이지 않도록 했다.

위치는 이동하지 않고 새로운 면도 추가하지 않는다. 런타임의 메모리 사본만 처리하므로 원본 GLB와 모델 배포 지문은 바뀌지 않는다. 정점 법선과 공유 정점의 관계는 [Three.js 공식 BufferGeometry 문서](https://threejs.org/docs/pages/BufferGeometry.html#computeVertexNormals), 실제 평활화 구현은 설치된 `three/addons/utils/BufferGeometryUtils.js`를 확인했다.

## 두 모델 전수 확인

Node 24.21.0에서 아래 명령으로 원본을 읽고 화면과 같은 처리를 수행했다.

```bash
cd frontend
node scripts/inspect-model-surfaces.mjs
```

| 항목 | Silverado | Ram |
|---|---:|---:|
| 메시 수 | 986 | 950 |
| 처리 전 삼각형 | 992,572 | 630,252 |
| 처리 후 삼각형 | 718,586 | 620,619 |
| 감소율 | 27.60% | 1.53% |
| 처리 전 정점 | 333,537 | 348,853 |
| 처리 후 정점 | 831,205 | 445,802 |
| 원본에 없던 위치로 이동한 정점 | 0 | 0 |
| 비정상 법선 | 0 | 0 |
| 모델 전체 경계 상자 | 동일 | 동일 |

모서리마다 다른 법선을 쓰려면 정점을 나눠야 하므로 **정점 수는 늘었다**. 이번 작업은 표면 품질 개선이며 메모리·프레임 속도 개선을 주장하지 않는다. 원본 파일 해시도 README에 기록된 값과 같았다: Silverado `d608c0bc…`, Ram `f8532a1d…`.

## 검사

- `geometry.test.ts` 5개: 중복·뒤집힌 면·면적 0 제거, 원본 불변, 완만한 곡면 평활화, 직각 모서리 유지, 메시 공유 범위·빈 결과, 비색인 입력·위치 보존.
- Node 24에서 `npm ci`, `npm run lint`, `npm run build`, `npm test`: 통과, 프런트 전체 79개. 기존 쇼룸 동적 청크의 500KB 경고는 남는다.
- `uv run ruff check .`, `uv run ruff format --check .`, `uv run pytest`: 통과, Python 498개 통과·16개 생략(시험 DB 미설정), 기존 경고 1개.
- Chrome 직접 연결에서 Silverado·Ram 외관, 흰색/파란색 차체, 조향 부품 선택·투시 표시를 확인했다. 캡처된 경고·오류 로그는 0건이었다. 네이티브 창 캡처가 이전 프레임을 반환해 직접 탭 연결로 다시 확인했다.
- 기존 `frontend/.vite/` 생성 캐시가 린트 대상에 포함돼 `.gitignore`에 제외했다. 캐시 파일은 지우지 않았다.

원본 단순화 모델의 일부 틈·불규칙한 그릴·패널 형상은 남아 있다. 실제 차체 형상을 다시 만드는 리모델링이나 세분화는 이번 범위에 포함하지 않았다.
