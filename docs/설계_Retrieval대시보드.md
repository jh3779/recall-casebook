# Retrieval 대시보드 설계

## 목적과 경계

검색 결과를 다시 판정하거나 점수화하지 않고, 사용자가 이미 받은 선례의 구조와 근거 가용성을
빠르게 훑게 한다. 기존 선례 목록·상세 화면은 그대로 두고, 검색 완료 뒤 `선례 상세`와
`분석 대시보드`를 전환한다. 대시보드는 `/search`의 `SearchResponse`만 사용하며 8D 작성 보조의
`EvidencePacketV1`과는 별도다.

모든 수치는 현재 화면에 반환된 고객사 최대 5건과 다른 회사 상위 10건만 집계한다. 전체 NHTSA
통계, 검색 확률, 위험도, 공급사 품질 점수로 해석하지 않는다.

## 화면 구성

1. **응답 요약**: 표시된 선례, 원인 글이 있는 카드, 조사 연결, 고유 `dup_group` 수.
2. **근거 흐름도**: 질문에서 현재 결과를 거쳐 FLAT_RCL, Part 573, NHTSA 조사로 이어지는 계층.
3. **원인 원문 상태**: `filled`, `stated_unknown`, 그 밖의 원문 없음 상태를 구분한다.
4. **부품 분류와 접수 연대기**: 고유 `CAMPNO` 기준 분포를 보여 준다.
5. **공급사 원문 표기**: 현재 결과의 `573.supplier_names`를 철자 그대로 묶어 등장 캠페인과
   부품을 보여 준다.
6. **근거 가용성 매트릭스**: 선례별 원인 글·조사·생산 기간·공급사 표기의 있음/없음만 보여 준다.
7. **판본 정보**: snapshot, build, model을 화면 하단에 유지한다.

대시보드 상단의 검색어는 응답 fixture의 고정 문자열이 아니라 사용자가 마지막으로 검색 버튼을
눌렀을 때의 질문을 별도 상태로 보존해 표시한다. 입력만 바꾸고 검색하지 않은 경우에는 이전
응답이 유지됨을 결과 전환 영역에 알린다.

## 공급사 프로필 해석 제한

현재 API는 검색 결과 카드의 공급사 원문만 전달하고 공급사 fact의 573 파일 출처는 전달하지
않는다. 따라서 이 화면은 **현재 표시 결과 안의 관측치**이며, 동일 회사의 법인명·철자 변형도
합치지 않는다. 건수는 공급 물량, 불량률, 책임 또는 품질 수준을 뜻하지 않는다.

573 보고서 전체를 대상으로 한 공급사 리콜 이력 프로필은 다음이 선행되어야 한다.

- 공급사 값마다 캠페인·파일·PDF SHA-256·제출일을 전달하는 출처 계약
- 사람이 검토한 공급사 이름 대응표와 원문 표기 병행 표시
- 보고서 공급사 칸의 결측률과 집계 분모 표시
- 순위·점수 없이 부품·고장 유형·CAMPNO를 탐색하는 별도 API

## 시각 원칙

- 기존 검색 화면의 남색·회색 토큰, 글꼴, 카드와 여백 체계를 재사용한다.
- 빨강/초록의 판정 색을 쓰지 않고, 파랑과 중립색으로 “있음/없음”만 구분한다.
- 다이어그램과 차트의 숫자는 모두 텍스트로도 표시해 색에만 의존하지 않는다.
- 근거 매트릭스는 색점만 쓰지 않고 `있음`·`없음`을 함께 적는다.
- 모바일에서는 흐름도를 세로로 바꾸고, 근거 매트릭스만 가로 스크롤을 허용한다.
