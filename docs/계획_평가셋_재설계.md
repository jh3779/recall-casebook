# 평가셋 재설계 — 573 작성 에이전트 방향에 맞는 평가지표 (제안, 팀 결정 전)

> 작성: 이승노(검색 성능 개선 실험 담당, [DEC-060](../.agent/DECISIONS.md)) · 2026-10-15 · 상태: **제안.** 도구와 시트는 만들었지만 **사람 표시가 없는 시트**다. 결과 수치는 아직 없다.
> 관련: [`계획_573_작성에이전트.md`](계획_573_작성에이전트.md)(방향), [`계획_P3_리랭커시험.md`](계획_P3_리랭커시험.md)(순서 시험), [`기획_결함선례.md`](기획_결함선례.md) 6절(현행 시험지)

## 1. 왜 바꾸나 — 현행 749문항 평가셋을 이 방향의 기준으로 쓸 수 없다

2026-10-15 검색 보완 시험에서 사전·약어·동의어·어간·색인 변형이 모두 ±0.01로 오르지 않았다. 원인을 따져 보니 **검색이 아니라 평가셋이 제품이 하려는 일을 재지 못한다**는 쪽에 가깝다. 규칙에 맞게 만들었다는 것(정답을 지어내지 않음)은 질문과 정답이 올바르다는 뜻이 아니다.

| 문제 | 근거 (직접 확인한 범위) |
|---|---|
| 정보 없는 질문 | 100자 미만 115개(15%), "DD"·"SEE ATTACHED SUMMARY." 같은 질문. 이 구간 H@10 0.26 (400자 이상은 0.86) |
| 질문과 정답이 다른 주제 | 원문 14문항을 열어 본 중 사례 확인(예: EA86029 — 질문은 후륜 축 중량·제동 용량, 정답 카드는 휠 용접부 균열). **전체에서 몇 %인지는 모른다** |
| 정답이 행정적 연결 | 정답 = 정부 기록에서 조사에 연결된 리콜. 글이 같은 이야기를 한다는 보장이 없고, 조사 1건에 정답이 1~몇 건뿐이라 쓸 만한 다른 선례가 1위여도 오답 |
| 질문이 제품의 입력이 아님 | 정부 조사관 문체("IN ITS LETTER DATED …"), 날짜·건수 포함. 엔지니어가 쓰는 결함 설명이 아님 |
| 시간 순서가 거꾸로 | 정답 리콜의 99.6%가 조사 시작 뒤 접수 — "과거 선례 찾기"가 아님 |

**결론**: 이 평가셋 위의 점수 변화(0.542 포함)는 제품 품질에 대한 정보로 쓰지 않는다. 앞서 낸 "확장은 효과 없음"도 **효과가 없다는 증거가 아니라 이 평가셋으로는 잴 수 없다는 증거**다. 방향이 바뀌었으므로(573 작성 에이전트) 평가도 새로 만든다.

## 2. 가장 중요한 원칙 — 재현율이 높게 나오도록 평가를 만들지 않는다 (과도학습 방지)

평가셋을 "잘 맞는 질문"으로 채우면 점수는 오르지만 의미가 없다. 아래 장치를 **결과를 보기 전에** 고정하고, 도구와 시험으로 지킨다.

| # | 장치 | 어떻게 지키나 |
|---|---|---|
| S1 | **질문·후보를 검색 결과로 고르지 않는다** | 표본은 시드 고정 무작위(`eval_v2.pick_queries`가 검색을 호출하지 않음 — 시험으로 고정). 고르는 규칙은 질문 글·카드 칸(유형·접수일·글 길이·부품 분류)만 쓴다 |
| S2 | **표시는 시스템을 가리고, AI 표시는 분리·보정한다** | 시트에 시스템 이름·순위 칸이 없다. 대응표(`pool_key.json`)는 표시자에게 주지 않는다. 사람 표시가 기준이고, 독립 AI 심사자의 표시는 `source=ai`로 따로 보고하며 사람 보정 전에는 합격 판정에 쓰지 않는다(2.1절) |
| S3 | **일부러 틀린 후보를 섞는다(통제 후보)** | 풀에 "같은 분류 무작위 5개"·"다른 분류 무작위 3개"를 섞는다. 표시자가 후하면(통제 후보를 관련이라고 표시) 그 시트는 무효 |
| S4 | **자명한 기준선보다 나아야 유효** | 키워드 한 줄 기준선을 항상 같이 잰다. 지표가 그걸 이기지 못하면 그 평가는 무효 (R2 — 아래 4절의 누출 수치) |
| S5 | **걸러낸 문항은 사람의 표시로만, 전체와 함께 보고** | 무효 문항 제외는 사람이 "답할 수 없는 질문/정답이 질문과 무관"으로 표시한 것만 쓴다. 제외 전 전체 점수와 제외 후 점수, 제외 수·사유를 **같이** 보고한다. 무효가 절반을 넘으면 거르지 않고 평가셋을 다시 만든다 |
| S6 | **시험 구간은 한 번만 연다** | 시간으로 개발·검증·시험을 나누고(4절), 임곗값·규칙은 개발·검증에서만 고정한다. 시험 구간은 마지막에 한 번 잰다 |
| S7 | **사전 고정** | 규칙·시드·표본 수·합격선·지표를 이 문서에 커밋한 뒤에 시스템을 돌린다. 결과를 보고 바꾸면 그 평가는 무효, 새 평가로 다시 한다 |
| S8 | **재현율만 보지 않는다** | 짝 지표(정밀도·특이도)와 구간(Wilson 95%), 문항 수를 항상 같이 낸다. "전부 관련/전부 양성"이라고 답하는 시스템이 이길 수 없게 한다 |
| S9 | **어려운 문항을 지우지 않는다** | 난이도 구간(질문 정보량, 부품 분류)을 미리 정해 구간별로 보고한다. 쉬운 구간만 보이게 하지 않는다 |
| S10 | **새 시스템 추가 시 풀 편향을 인정** | 풀링 평가는 풀에 없던 후보를 새 시스템이 올리면 불리하다. 새 시스템의 상위 10 중 **표시 안 된 후보만** 추가로 표시하고, "표시된 비율(judged coverage)"을 함께 낸다 |

### 2.1 "표시자"와 자동화 — 무엇을 기계가 하고 무엇을 사람이 하나

**표시자** = 시트의 빈 칸(`label` 등)을 직접 채우는 사람이다. E0 감사 시트(100줄)는 "질문만으로 어떤 결함인지 가릴 수 있나(yes/no/unsure)", "정답 카드가 질문의 결함과 맞나(yes/no/unsure)"를, E1 풀링 시트(996줄)는 "후보가 같은 부품·같은 고장인가(0/1/2)"를 적는다. 이 표시가 평가의 **정답지**가 된다. 표시자를 정한다는 것은 이 일을 누가 할지 정하는 것이다(질문·시트를 만든 AI 세션은 하지 않는다 — S2).

| 자동화한다(코드) | 사람이 한다 | 하지 않는다 |
|---|---|---|
| 시드 고정 표본 뽑기, 시트·대응표 생성, 시스템 가리기, **독립 AI 심사(`source=ai`)** | 사람 보정 표시(AI와의 일치도·후함 측정), 판정 근거 확인 | 사람 보정 없는 AI 점수로 합격 판정 |
| 원본 칸 변조 검사(해시), 허용 값 검사 | 두 표시자가 따로 표시(일치도용 겹침) | 시스템 정보를 심사자에게 보여 주기 |
| 통제 후보 검사, kappa, 표시된 비율, 의견 불일치 제외, 시스템별 점수(`r1-score`) | 의견 불일치 항목의 합의 | AI 표시와 사람 표시를 합쳐 한 점수로 내기 |
| 749문항 **객관 플래그**(글 길이·내용 단어 수·정답과 단어 겹침 0, `question-flags`) — 무효 규모의 대략을 사람 표시 없이 본다. 의심일 뿐 문항을 거르지 않는다 | | |
| R2 누출 점검(키워드 기준선), Wilson 구간·AUC·민감도 계산 | | |

**독립 AI 심사자는 쓴다 — 단, 환각이 아니라 편향 때문에 장치를 붙인다 (2026-10-15 규칙 변경 반영).** `AGENTS.md` 5절 2항의 "평가 질문·정답을 AI로 지어내지 않고…", "AI 세션에서 질문을 만들거나 다듬었다면 그 세션에서 이어서 정답을 표시·검증하지 않는다" 문장이 삭제됐다(작업 폴더의 **커밋 전 수정** — 팀 합의·PR 전이고 `origin/main`의 규칙·표시 안내서·DEC-055/060은 그대로다. 삭제 뒤 "같은 세션에서 이어 하게 되면 멈추고…"만 앞 문장 없이 남아 있어 정리가 필요하다). 환각(없는 내용을 만들어 냄)과 달리 **기존 글에 근거한 검수·관련도 판단**은 규칙 위반이 아니라는 구분에 동의한다. 다만 AI 표시에는 환각과 별개의 위험이 남는다: 심사자와 검색기의 **오류가 같은 방향으로 움직여 재현율이 후하게 나올 수 있다.** 그래서 아래 장치를 붙여 쓴다.

| 장치 | 내용 |
|---|---|
| 독립 | 새 컨텍스트의 별도 에이전트(모델 `sonnet`)가 심사한다. 시스템 이름·순위·검색 방식을 보지 못하고 시트의 **텍스트 열만** 받는다. 다른 파일은 열지 않도록 지시한다 |
| 분리 보고 | AI 표시는 `labeler_id=AI-…`·`note=source=ai`로 **사람 표시와 합치지 않고 따로** 저장·보고한다. "사람 보정 전"이라고 표기한다 |
| 통제 후보 | 같은 풀에 섞은 통제 후보로 AI가 후한지 확인한다(5절 합격선을 그대로 적용) |
| 2단계 감사 | 감사는 질문만 보고 판단하는 단계와 정답 카드까지 보는 단계를 **서로 다른 에이전트**가 한다(질문만 볼 때 정답에 끌리지 않게) |
| 프롬프트 고정 | 아래 부록의 프롬프트를 시험 전에 고정했고 결과를 보고 바꾸지 않는다 |
| 사람 보정(남은 일) | 사람이 일부(감사 100·풀링 일부)를 표시해 AI와의 kappa·후함을 잰다. **보정 전에는 AI 점수를 합격 판정에 쓰지 않는다** |
| 질문 생성 | AI가 만드는 "예상 질문"은 질문 카드의 **기존 글을 바꿔 쓴 것**만 허용하고, 정답 후보 카드 글에서 만들지 않는다. 바꿔 쓴 질문과 정답 후보의 단어 겹침을 재서 누수(질문이 정답을 베낌)를 점검하고, 원문 질문과 바꿔 쓴 질문의 점수를 **둘 다** 보고한다. 이번에 쓴 R1 질문은 AI가 만든 것이 아니라 573 시대 리콜 카드의 실제 결함 글이라 해당 없음(바꿔 쓴 질문은 후속) |

## 3. 새 평가 구성

| 평가 | 재는 것 | 질문(입력)의 출처 | 정답(기준)의 출처 | 핵심 지표 | 도구 |
|---|---|---|---|---|---|
| **E0 현행 749문항 감사** | 현행 시험지가 얼마나 무효인가 | 현행 749문항에서 시드 100개 | **사람 표시**: ⓐ질문만으로 답을 가릴 수 있는가 ⓑ정답 카드가 질문의 결함과 같은 부품·고장인가 | 무효 비율과 Wilson 구간, 둘 다 yes인 비율 | `eval_v2 audit-sheet` / `audit-score` |
| **E1 선례 증거(R1)** | 에이전트가 쓸 만한 선례를 상위 10에 올리는가 | **573 시대 리콜 카드의 결함 글**(제조사가 실제 쓴 결함 설명 — 엔지니어가 쓸 입력과 같은 종류, AI 작성 아님)을 질문으로, 정답 후보는 그 리콜보다 **먼저** 접수된 카드 | **사람 풀링 표시**(관련도 0·1·2) | 상위 10에 관련도 2가 있는 질문 비율(Hit), nDCG@10, 정밀도@10, **표시된 비율** | `eval_v2 r1-pool` |
| **E2 보고 대상 신호(R2)** | 리콜로 이어질 사례에 신호를 내는가 | 조사 **개시 시점** 입력(결과가 새지 않은 텍스트) | **정부 기록**(리콜 연결 vs 리콜 없이 종결) | 특이도 고정 시 민감도, AUC, **키워드 기준선과 차이** | `eval_v2 r2-counts`(누출 점검) |
| **E3 573 초안 품질** | 초안이 규칙을 지키는가 | 엔지니어 입력(합성 아님, 사람이 준비) | 자동 검사 + 사람 검토 | 문장 출처 태그 100%, 인용 원문 일치 100%, 판정어 0건, 칸 충족도 | 구현 시(M4) |
| **E4 정보 부족 입력 처리** | 정보가 모자라면 더 받으려 하는가 | E0·E1에서 사람이 "답할 수 없음"으로 표시한 질문 | 사람 표시 | 안내 비율(미응답이 아니라 보류) | 구현 시 |

E4는 중요하다: 정보 없는 질문(15%)을 "틀린 것"으로 세면 평가가 흐려지고, 빼 버리면 쉬운 문항만 남는다(S5). **정보 부족을 알아채고 되묻는 것**을 따로 재는 지표로 만든다.

## 4. R2(보고 대상 신호)의 데이터와 누출 — 직접 측정

데이터: `FLAT_INV`의 조사 5,349건 중 PE·EA 4,263건(조사 개시 뒤 리콜로 이어졌는가는 `CAMPNO` 연결 유무). 아래는 `eval_v2 r2-counts` 출력이다.

| 구간(조사 개시) | PE·EA 수 | 리콜 연결 | 리콜 없이 종결 | 아직 진행 중(연결 없음) |
|---|---|---|---|---|
| 2010 미만 | 3,732 | 938 | 2,793 | 1 |
| 2010~2019 | 364 | 196 | 166 | 2 |
| 2020 이상 | 167 | 72 | 61 | 34 |

- 요약문이 100자 이상인 종결 조사: 양성 755 · 음성 976.
- **누출(S4)**: 요약문에 `recall`이라는 글자가 들어 있는지만 보는 **키워드 한 줄이 민감도 0.793·특이도 0.882**를 낸다(`recall|campaign|573`이면 0.815·0.826). 현행 `FLAT_INV` 요약문은 조사가 끝난 뒤의 판본이라 결과가 새어 있다. 그대로 쓰면 "recall 글자 찾기"가 90% 재현율에 근접해 의미가 없어진다.
- **그래서 R2는 다음을 만족해야 유효하다**:
  1. 입력은 **조사 개시 시점 텍스트**(ODI Resume, 2007년 이후 개시분에서 확인된 PDF — 시점 평가가 이미 같은 방식으로 질문 판본을 옮김)만 쓴다. 결과를 알려 주는 단어·번호를 마스킹하는 것은 보조이고, 마스킹만으로는 부족하다.
  2. 시스템의 민감도가 **같은 특이도에서 키워드 기준선보다 유의하게 높아야** 한다(Wilson 구간이 겹치지 않을 것).
  3. 시간 분할: 개발 2010 미만, 검증 2010~2019, 시험 2020 이상. **시험 구간은 종결된 133건(양성 72·음성 61)뿐이라 구간이 넓다** — 민감도 0.90이 양성 72건이면 Wilson 95% 구간이 약 0.81~0.95다. 이 한계를 보고에 적는다.
- 라벨 잡음: "리콜 없이 종결 = 안전 결함 아님"이 아니다(제조사가 자발적으로 조치했거나 다른 이유로 종결). 정부 기록 기반 **대리 라벨**이라고 밝힌다.

## 5. R1(선례 증거) 설계 — 구체

**질문 고르기**(`pick_queries`, 검색을 보지 않는다): 차량 리콜(유형 V)·접수 2015-01-01 이후·결함 글 80~600자, 부품 대분류를 돌아가며 분류당 최대 3개, 시드 `20261016`. 이 규칙은 질문 글·카드 칸만 쓴다.
**후보 풀**(`build_pool`): 질문 리콜보다 먼저 접수·다른 중복 묶음인 카드 중 BM25·뜻 검색·RRF 각 상위 10(시스템 합집합, 중복 제거) + 통제 후보(같은 분류 5·다른 분류 3). 후보 번호는 해시라 순서·시스템을 추측할 수 없다.
**표시 값**: `2` 같은 부품이고 같은 고장 방식 / `1` 같은 부품이지만 다른 고장 / `0` 다른 부품. 후보 글(결함)만 보여 준다.
**표시 규칙**: 두 사람이 따로 표시하고 약 25%를 겹쳐 일치도(Cohen kappa)를 잰다. 합격선은 **kappa ≥ 0.6, 통제 후보(다른 분류)의 관련 표시 < 5%, 통제 후보(같은 분류)의 `2` 표시 < 15%** — 미달이면 그 표시자의 시트는 무효(S3). 합격선은 시험 전에 고정했고 결과를 보고 바꾸지 않는다.
**규모**: 40문항이면 후보 996줄이라 한 사람이 몇 시간 걸린다. **최소판 20문항(약 500줄)**을 권한다. 지금 만든 시트는 40문항(`r1_pool_sheet.csv`, 로컬)이고 앞 20문항만 써도 된다.
**점수**: Hit(상위 10에 `2`가 있는 질문의 비율, 문항 수·Wilson 구간), nDCG@10, 정밀도@10(`≥1`), 표시된 비율. **새 시스템**이 오면 상위 10 중 표시 안 된 후보만 추가 표시한다(S10).

## 6. "목표 재현율 90%" — 이 지표로 다시 정의 (D5 제안)

| 지표 | 제안 합격선 | 비고 |
|---|---|---|
| R1 Hit(상위 10) | **≥ 0.90** (유효 질문, 정밀도@10 ≥ 0.4 와 함께) | 정밀도 하한은 D5에서 정한다 — 제안값 |
| R2 민감도 | **≥ 0.90**, 특이도 ≥ 0.80에서, 키워드 기준선보다 유의하게 높음 | 특이도 하한은 D5에서 정한다 — 제안값 |
| E3 | 모든 자동 검사 100%·판정어 0건 | 재현율과 합치지 않는다 |

**평가를 쉽게 만들어 90%를 맞추지 않는다.** 이 설계에서 90%에 못 미치면 못 미친 대로 보고한다. 질문·후보·합격선은 결과를 보기 전에 고정하고(S7), 못 미치는 이유를 분석해 시스템을 고친다.

## 부록 A. 고정한 AI 심사 프롬프트 (요약)

- **감사 1단계(질문만)**: "질문 글만으로 ⓐ어느 차량 부품·시스템인지 ⓑ어떤 종류의 고장인지 **둘 다** 가릴 수 있는가 — yes/no/unsure. 특정 리콜을 찾아보거나 추측하지 말고 다른 파일을 열지 말 것."
- **감사 2단계(질문 + 정답 카드)**: "정답 카드(결함·결과)가 질문과 **같은 부품·같은 고장**을 말하는가 — yes(같은 부품·같은 고장)/no(다른 부품이거나 다른 고장·주제)/unsure."
- **풀링**: "질문 글(리콜 결함 설명)과 후보(앞서 접수된 리콜의 결함 설명)가 **2 = 같은 부품·같은 고장 방식 / 1 = 같은 부품·다른 고장 / 0 = 다른 부품**. 제조사·연식은 무시, 특정 리콜을 추측하지 말고 후보가 어떻게 검색됐는지 추정하지 말 것."
- 모든 출력은 정해진 열(`label`, `reason`≤12단어)만, 행마다 하나, 건너뛰지 않음. 시스템 이름·순위는 입력에 없다.

## 12. 예상 질문 세트와 누수 점검 — 사전 고정 규칙 (결과를 보기 전, 2026-10-15)

**목적**: R1의 질문(573 시대 리콜 카드의 결함 글)은 제조사의 서식·문장이라 후보 중 같은 제조사·같은 문장 서식의 카드가 유리할 수 있다(복사형 누수). 엔지니어가 실제로 쓸 법한 **짧은 예상 질문**으로 바꿔 쓴 세트를 만들고, **원문 질문과 바꿔 쓴 질문의 점수를 둘 다 보고**해 누수·서식 의존을 재 본다.

**생성 규칙(고정)**
1. 입력은 질문 카드의 **결함 글 하나뿐**이다(40개, 질문 선택 규칙·시드는 5절 그대로). 정답 후보·검색 결과·다른 카드는 생성 에이전트에 주지 않는다.
2. 에이전트는 새 컨텍스트이고 한 번에 10개씩 4개가 작성한다. **글에 없는 부품·고장·원인·결과를 더하지 않는다.** 영어 한 문장 또는 두 문장, 6~45단어, 엔지니어가 신고·문의로 쓸 법한 문체.
3. 제조사·브랜드·모델·연식·날짜·숫자·리콜 번호를 쓰지 않는다.
4. 같은 구절을 그대로 베끼지 않는다: **원문과 연속으로 겹치는 단어가 7개 이상이면 실패.**

**기계 검사(고정)** — `eval_v2 paraphrase-check`: 숫자 포함, 브랜드 이름 포함(`strip_brands`), 6단어 미만·45단어 초과, 원문과 연속 겹침 7단어 이상 → **하드 실패**. 실패 항목은 **한 번만** 다시 생성하고(같은 프롬프트에 위반 사유만 덧붙임) 그래도 실패하면 **빼고 개수를 보고**한다. 보고 항목: 원문과의 내용 단어 Jaccard 평균, 원문에 없는 단어 비율(새 단어), 최장 연속 겹침.

**충실도 검사(고정)** — 별도 에이전트가 "바꿔 쓴 문장이 원문에 없는 부품·고장·원인·결과를 더했는가"(no 더함 / yes 더함 / 불확실)를 본다. 더한 것으로 판정된 항목은 빼고 개수를 보고한다. **AI가 지어낸 내용이 정답에 새는 것을 막는 검사**다.

**검색·표시(고정)**: 같은 40개 질문 카드·같은 후보 자격(질문보다 먼저 접수·다른 중복 묶음)·같은 시드로 풀을 다시 만든다(검색 질의만 바꿔 쓴 질문). 관련도의 기준은 **원문 결함 글**이다 — 질문의 표현이 아니라 실제 결함이 같은가를 본다. 이미 표시된 (질문, 후보) 쌍은 재사용하고 **새 후보만** 같은 독립 AI 심사 프롬프트(부록 A)로 표시한다(S10).

**누수 점검 항목(고정)**: ① 원문 질문 vs 예상 질문의 Hit@10·nDCG@10·정밀도@10 차이(Wilson, 문항별 좋아짐/나빠짐) ② 상위 10 중 질문과 **같은 제조사** 후보의 비율(원문·예상) ③ 질문 글과 후보 글의 단어 겹침이 매우 높은 **복사형 후보**(내용 단어 Jaccard ≥ 0.6) 수와 그것을 뺀 Hit@10. 원문 점수가 예상 점수보다 크게 높고 같은 제조사·복사형 후보가 많으면 원문 질문 평가는 서식 의존으로 부풀려졌다고 본다.

**해석 규칙(고정)**: 두 점수의 차이가 Wilson 구간 안이고 같은 제조사·복사형 비율이 낮으면 "서식 의존 증거 없음"이고, 그렇지 않으면 예상 질문 점수를 R1의 주 지표로 삼는다. 어느 쪽이든 두 점수를 **함께** 보고한다.

## 13. 예상 질문 세트와 누수 점검 — 결과 (2026-10-15, AI 표시·사람 보정 전)

**생성·검사**: 질문 카드 40개의 결함 글을 독립 에이전트 4개가 바꿔 썼다. 기계 검사에서 5개가 7단어 이상 베껴 써서 한 번만 다시 생성했고(규칙대로) 40개 모두 통과했다. 충실도 검사에서 **5개가 원문에 없는 내용을 더했다**고 판정돼(Q023·Q029·Q034·Q035·Q040) 빼서 **35개**가 남았다. 바꿔 쓴 질문과 원문의 내용 단어 Jaccard 평균 0.225, 원문에 없는 새 단어 비율 0.576, 최장 연속 겹침 평균 4.0단어.
> 정정: 이 절을 쓰는 과정에서 충실도 검사 에이전트 한 개가 결과 파일을 고쳐 쓰기 전에 읽은 값(7개 더함)을 한 번 잘못 말했다. 최종은 5개이고 풀 생성에 쓴 파일도 최종본이다.

**점수 비교(같은 35개 질문)** — Hit@10 = 관련도 2가 상위 10에 있는 질문 비율, 후보는 모두 독립 AI 심사자가 표시(표시된 비율 1.0).

| 시스템 | Hit@10 원문 → 예상 | 좋아진/나빠진 질문 (McNemar p) | nDCG@10 원문 → 예상 | 정밀도@10(관련도≥1) 원문 → 예상 |
|---|---|---|---|---|
| BM25 | 0.771 → 0.829 | 6 / 4 (0.75) | 0.679 → 0.874 | 0.494 → 0.826 |
| 뜻 검색 | 0.657 → 0.771 | 8 / 4 (0.39) | 0.636 → 0.793 | 0.377 → 0.749 |
| RRF(현행) | 0.714 → 0.800 | 6 / 3 (0.51) | 0.721 → 0.845 | 0.409 → 0.806 |

예상 질문 35개 전체 기준: BM25 Hit@10 0.829 (Wilson 0.67~0.92), 뜻 검색 0.771 (0.61~0.88), RRF 0.800 (0.64~0.90). 통제 후보 검사 통과(다른 분류 관련 표시 1.0%, 같은 분류 `2` 표시 8.2%).

**누수 점검 3항목**
1. **점수 차이**: Hit@10 차이는 모두 Wilson 구간 안이다(p 0.39~0.75). 그러나 **nDCG와 정밀도는 크게 다르다**(정밀도 0.41 → 0.81 등).
2. **같은 제조사 비율(상위 10)**: 원문 질문 **68~81%**(BM25 0.680·뜻 검색 0.810·RRF 0.772) vs 예상 질문 **3~5%**(0.049·0.031·0.046). 원문 질문은 제조사 이름과 "X is recalling certain … vehicles" 서식이 들어 있어 **같은 제조사의 먼저 접수된 카드가 상위를 채운다.** 관련 없는 카드가 많이 섞여 정밀도·nDCG가 낮아진다.
3. **복사형 후보(내용 단어 Jaccard ≥ 0.6)**: 원문 풀 5개 · 예상 풀 6개(상위 10 자리의 1~2%)로 **거의 없다.** 이것을 빼도 결론이 같다(RRF Hit@10 원문 0.714 → 0.657, 예상 0.800 → 0.771).

**사전 고정한 해석 규칙(12절)을 적용**: Hit@10 차이는 구간 안이지만 **같은 제조사 비율이 원문에서 높으므로(68~81%) 원문 질문 평가는 제조사·서식 의존이 있다**고 본다. 따라서 **R1의 주 지표는 예상 질문 점수**로 하고 원문 질문 점수는 함께 보고한다.

**읽는 법과 한계**
- 원문 질문의 약점은 점수를 **부풀린 것**이 아니라 제조사 서식이 상위를 채워 **정밀도·순위 품질을 떨어뜨린** 것이다. Hit@10만 보면 이 차이가 가려진다.
- 예상 질문은 **제조사 이름을 빼도록 규칙으로 정했으므로** 같은 제조사 비율이 낮은 것은 부분적으로 설계의 결과다. 실제 엔지니어도 보통 자기 회사 이름을 질문에 쓰지 않는다고 가정했다(미확인).
- **0.90 목표와의 관계**: 예상 질문 Hit@10의 점 추정은 BM25 0.829·RRF 0.800으로 0.90에 못 미친다(구간 상한은 0.9 안팎). 평가가 쉽게 만들어진 것은 아니다.
- **한계**: 질문 35개·AI 심사자 한 종류(사람 보정 없음). 예상 질문은 AI가 바꿔 쓴 것이라 실제 엔지니어 문체와 같은지 사람이 확인하지 않았다. 질문 작성 모델과 심사 모델이 같은 계열(`sonnet`)이다 — 심사자는 질문이 아니라 **원문 결함 글**과 후보를 비교해 질문 표현이 직접 영향을 주지는 않지만, 같은 계열의 선호가 섞였는지는 사람 보정으로 확인해야 한다. 충실도 검사 두 에이전트의 엄격도가 달랐다(한쪽 0/20, 다른 쪽 5/20 더함).

## 14. 100문항 확대와 전문가 역할 AI 검수 — 사전 고정 프로토콜 (결과를 보기 전, 2026-10-15)

**배경**: 현재 실무자(품질 엔지니어)가 없어 사람 보정이 불가능하다. 그래서 **자동차 품질·제품안전 엔지니어 역할을 가진 AI 검수 에이전트**를 쓰되, 실무자 검증을 대체하는 것이 아니라 **"전문가 역할 AI 검수 — 실무자 검증 전"**이라고 모든 결과에 표기한다. 대신 아래 장치로 AI 검수 자체의 신뢰를 재 본다.

**규모·질문**: R1 질문 카드를 40 → **100개**로 늘린다(시드 `20261016`, 같은 선택 규칙이라 앞 40개는 그대로). 예상 질문은 같은 규칙·검사로 만든다. 앞 40개에서 이미 만든 예상 질문과 충실도 판정은 재사용하되 **새 하드 규칙(질문에 원인 표현 금지 — `due to`·`caused by`·`because`·`resulting from`·`as a result of`·`root cause`·`attributed to`)을 소급 적용**해 실패한 질문은 한 번만 재생성하고 그래도 실패하면 뺀다. 최종 질문 수는 제외 사유와 함께 보고한다(100개가 되지 않을 수 있다).

**검수자(고정)**
- **전문가 A**(`opus`): 아래 부록 B의 전문가 역할·평가표(고장 방식 분류 고정 목록)를 받는다. **모든 후보 행**을 표시한다.
- **검수자 B**(`sonnet`, 부록 A의 일반 프롬프트): 앞 40개 질문 쪽은 이미 표시한 값(1,000행)이 있고, 새 질문 쪽은 **시드 고정 무작위 30%**를 추가로 표시한다.
- 두 검수자는 시스템 이름·순위를 보지 못하고 텍스트 열만 본다. 서로의 표시를 보지 못한다.
- 검수 에이전트는 **다른 파일을 열지 않고 특정 리콜을 찾아보지 않도록** 지시한다.

**신뢰 점검(합격선, 고정)**: 두 검수자의 겹친 후보에서 **kappa ≥ 0.6**, 한쪽이 체계적으로 더 후한 비율의 차이 **≤ 0.10**, 통제 후보 검사(다른 분류 관련 표시 < 5%, 같은 분류 `2` 표시 < 15%)를 **두 검수자 모두** 통과. 미달이면 그 점수는 "신뢰 점검 미달"로 표시하고 합격 판정에 쓰지 않는다. 기준은 결과를 보고 바꾸지 않는다.

**점수(고정)**: **주 지표는 level-2**(같은 부품·같은 고장 방식) — Hit@10(상위 10에 `2`가 있는 질문 비율), **정밀도@10 level-2**, nDCG@10. "부품만 같음(≥1)" 정밀도는 보조로만 쓴다(질문이 부품을 알려 주므로 쉽다). 전문가 A의 표시를 주로 쓰고, 검수자 B 표시와의 차이는 별도 보고한다. 표시된 비율 1.0을 확인한다.

**질문 현실성 검수(고정)**: 별도 전문가 에이전트가 예상 질문마다 "품질 엔지니어가 결함 상황을 설명하며 검색에 쓸 법한가(yes/no/unsure)", "기술적으로 말이 되는가(yes/no/unsure)"를 본다. 결과는 보고하고 질문을 고치지 않는다.

**해석**: 이 점수는 실무자 검증이 없는 AI 검수 값이다. 0.90 목표는 level-2 지표에서 구간 하한까지 따져 판단하고, 못 미치면 못 미친 대로 보고한다.

## 부록 B. 전문가 역할 검수 프롬프트·평가표 (고정)

**역할**: 15년 경력의 자동차 품질·제품안전 엔지니어(파워트레인·섀시·전장·ADAS/소프트웨어). 목적은 결함 선례 검색 평가의 관련도 표시다.

**기준**: 질문 글(결함 설명)과 후보(앞서 접수된 리콜의 결함 설명)를 비교한다. 제조사·연식·모델은 무시한다.
- **2 = 같은 부품(또는 같은 부품군의 직접 대체·좌우·앞뒤 등가 부품) 그리고 같은 고장 방식 분류**
- **1 = 같은 시스템이지만 고장 방식 분류가 다르거나, 같은 시스템의 다른 부품**
- **0 = 다른 시스템**

**고장 방식 분류(고정 목록)**: 유체·가스 누설 / 구조 파손·균열·분리 / 체결 불량·풀림·토크 불량 / 전기 단락·단선·커넥터·배선 / 과열·열 이벤트·발화 / 소프트웨어·로직·캘리브레이션 / 마모·부식·열화 / 이물·오염 / 조립 오류·잘못된 부품·누락 / 감지·센싱 오류 / 의도치 않은 작동·기능 불능 / 기타. 후보와 질문이 같은 분류여야 `2`다.

**지킬 것**: 두 글만 보고 판단한다. 특정 리콜·제조사·모델을 찾아보거나 추측하지 않는다. 다른 파일을 열지 않는다. 후보가 어떻게 검색됐는지 추정하지 않는다. 행마다 한 줄(label, 공학적 이유 12단어 이내).
