# 평가셋 재설계 — 573 작성 에이전트 방향에 맞는 평가지표 (제안, 팀 결정 전)

> 작성: 이승노(검색 성능 개선 실험 담당, [DEC-060](../.agent/DECISIONS.md)) · 2026-10-15 · 상태: **제안.** 도구와 시트는 만들었지만 **사람 표시가 없는 시트**다. 결과 수치는 아직 없다.
> 관련: [`계획_573_작성에이전트.md`](계획_573_작성에이전트.md)(방향), [`계획_P3_리랭커시험.md`](계획_P3_리랭커시험.md)(순서 시험), [`기획_결함선례.md`](기획_결함선례.md) 6절(현행 시험지)

## 1. 왜 바꾸나 — 현행 749문항 평가셋을 이 방향의 기준으로 쓸 수 없다

2026-10-15 검색 보완 시험에서 사전·약어·동의어·어간·색인 변형이 모두 ±0.01로 오르지 않았다. 원인을 따져 보니 **검색이 아니라 평가셋이 제품이 하려는 일을 재지 못한다**는 쪽에 가깝다. 규칙에 맞게 만들었다는 것(정답을 지어내지 않음)은 질문과 정답이 올바르다는 뜻이 아니다.

| 문제 | 근거 (직접 확인한 범위) |
|---|---|
| 정보 없는 질문 | 100자 미만 115개(15%), "DD"·"SEE ATTACHED SUMMARY." 같은 질문. 이 구간 H@10 0.26 (400자 이상은 0.86) |
| 질문과 정답이 다른 주제 | 원문 14문항을 열어 본 중 사례 확인(예: EA86029 — 질문은 후륜 축 중량·제동 용량, 정답 카드는 휠 용접부 균열). **전체에서 몇 %인지는 모른다** |
| 정답이 행정적 연결 | 정답 = 정부 기록에서 조사에 연결된 리콜. 글이 같은 이야기를 한다는 보장이 없고, 조사 1건에 정답이 1~몇 건뿐이라 쓸 만한 다른 선례가 1위여도 오답 |
| 질문이 제품의 입력이 아님 | 정부 조사관 문체("IN ITS LETTER DATED …"), 날짜·건수 포함. 엔지니어가 쓰는 결함 설명이 아님 |
| 시간 순서가 거꾸로 | 정답 리콜의 99.6%가 조사 시작 뒤 접수 — "과거 선례 찾기"가 아님 |

**결론**: 이 평가셋 위의 점수 변화(0.542 포함)는 제품 품질에 대한 정보로 쓰지 않는다. 앞서 낸 "확장은 효과 없음"도 **효과가 없다는 증거가 아니라 이 평가셋으로는 잴 수 없다는 증거**다. 방향이 바뀌었으므로(573 작성 에이전트) 평가도 새로 만든다.

## 2. 가장 중요한 원칙 — 재현율이 높게 나오도록 평가를 만들지 않는다 (과도학습 방지)

평가셋을 "잘 맞는 질문"으로 채우면 점수는 오르지만 의미가 없다. 아래 장치를 **결과를 보기 전에** 고정하고, 도구와 시험으로 지킨다.

| # | 장치 | 어떻게 지키나 |
|---|---|---|
| S1 | **질문·후보를 검색 결과로 고르지 않는다** | 표본은 시드 고정 무작위(`eval_v2.pick_queries`가 검색을 호출하지 않음 — 시험으로 고정). 고르는 규칙은 질문 글·카드 칸(유형·접수일·글 길이·부품 분류)만 쓴다 |
| S2 | **정답·관련도 표시는 사람, 시스템을 가린다** | 시트에 시스템 이름·순위 칸이 없다. 대응표(`pool_key.json`)는 표시자에게 주지 않는다. AI가 표시하지 않는다(AGENTS.md 5-2). 평가 질문을 만들거나 다듬은 AI 세션은 정답을 표시하지 않는다(DEC-024) |
| S3 | **일부러 틀린 후보를 섞는다(통제 후보)** | 풀에 "같은 분류 무작위 5개"·"다른 분류 무작위 3개"를 섞는다. 표시자가 후하면(통제 후보를 관련이라고 표시) 그 시트는 무효 |
| S4 | **자명한 기준선보다 나아야 유효** | 키워드 한 줄 기준선을 항상 같이 잰다. 지표가 그걸 이기지 못하면 그 평가는 무효 (R2 — 아래 4절의 누출 수치) |
| S5 | **걸러낸 문항은 사람의 표시로만, 전체와 함께 보고** | 무효 문항 제외는 사람이 "답할 수 없는 질문/정답이 질문과 무관"으로 표시한 것만 쓴다. 제외 전 전체 점수와 제외 후 점수, 제외 수·사유를 **같이** 보고한다. 무효가 절반을 넘으면 거르지 않고 평가셋을 다시 만든다 |
| S6 | **시험 구간은 한 번만 연다** | 시간으로 개발·검증·시험을 나누고(4절), 임곗값·규칙은 개발·검증에서만 고정한다. 시험 구간은 마지막에 한 번 잰다 |
| S7 | **사전 고정** | 규칙·시드·표본 수·합격선·지표를 이 문서에 커밋한 뒤에 시스템을 돌린다. 결과를 보고 바꾸면 그 평가는 무효, 새 평가로 다시 한다 |
| S8 | **재현율만 보지 않는다** | 짝 지표(정밀도·특이도)와 구간(Wilson 95%), 문항 수를 항상 같이 낸다. "전부 관련/전부 양성"이라고 답하는 시스템이 이길 수 없게 한다 |
| S9 | **어려운 문항을 지우지 않는다** | 난이도 구간(질문 정보량, 부품 분류)을 미리 정해 구간별로 보고한다. 쉬운 구간만 보이게 하지 않는다 |
| S10 | **새 시스템 추가 시 풀 편향을 인정** | 풀링 평가는 풀에 없던 후보를 새 시스템이 올리면 불리하다. 새 시스템의 상위 10 중 **표시 안 된 후보만** 추가로 표시하고, "표시된 비율(judged coverage)"을 함께 낸다 |

## 3. 새 평가 구성

| 평가 | 재는 것 | 질문(입력)의 출처 | 정답(기준)의 출처 | 핵심 지표 | 도구 |
|---|---|---|---|---|---|
| **E0 현행 749문항 감사** | 현행 시험지가 얼마나 무효인가 | 현행 749문항에서 시드 100개 | **사람 표시**: ⓐ질문만으로 답을 가릴 수 있는가 ⓑ정답 카드가 질문의 결함과 같은 부품·고장인가 | 무효 비율과 Wilson 구간, 둘 다 yes인 비율 | `eval_v2 audit-sheet` / `audit-score` |
| **E1 선례 증거(R1)** | 에이전트가 쓸 만한 선례를 상위 10에 올리는가 | **573 시대 리콜 카드의 결함 글**(제조사가 실제 쓴 결함 설명 — 엔지니어가 쓸 입력과 같은 종류, AI 작성 아님)을 질문으로, 정답 후보는 그 리콜보다 **먼저** 접수된 카드 | **사람 풀링 표시**(관련도 0·1·2) | 상위 10에 관련도 2가 있는 질문 비율(Hit), nDCG@10, 정밀도@10, **표시된 비율** | `eval_v2 r1-pool` |
| **E2 보고 대상 신호(R2)** | 리콜로 이어질 사례에 신호를 내는가 | 조사 **개시 시점** 입력(결과가 새지 않은 텍스트) | **정부 기록**(리콜 연결 vs 리콜 없이 종결) | 특이도 고정 시 민감도, AUC, **키워드 기준선과 차이** | `eval_v2 r2-counts`(누출 점검) |
| **E3 573 초안 품질** | 초안이 규칙을 지키는가 | 엔지니어 입력(합성 아님, 사람이 준비) | 자동 검사 + 사람 검토 | 문장 출처 태그 100%, 인용 원문 일치 100%, 판정어 0건, 칸 충족도 | 구현 시(M4) |
| **E4 정보 부족 입력 처리** | 정보가 모자라면 더 받으려 하는가 | E0·E1에서 사람이 "답할 수 없음"으로 표시한 질문 | 사람 표시 | 안내 비율(미응답이 아니라 보류) | 구현 시 |

E4는 중요하다: 정보 없는 질문(15%)을 "틀린 것"으로 세면 평가가 흐려지고, 빼 버리면 쉬운 문항만 남는다(S5). **정보 부족을 알아채고 되묻는 것**을 따로 재는 지표로 만든다.

## 4. R2(보고 대상 신호)의 데이터와 누출 — 직접 측정

데이터: `FLAT_INV`의 조사 5,349건 중 PE·EA 4,263건(조사 개시 뒤 리콜로 이어졌는가는 `CAMPNO` 연결 유무). 아래는 `eval_v2 r2-counts` 출력이다.

| 구간(조사 개시) | PE·EA 수 | 리콜 연결 | 리콜 없이 종결 | 아직 진행 중(연결 없음) |
|---|---|---|---|---|
| 2010 미만 | 3,732 | 938 | 2,793 | 1 |
| 2010~2019 | 364 | 196 | 166 | 2 |
| 2020 이상 | 167 | 72 | 61 | 34 |

- 요약문이 100자 이상인 종결 조사: 양성 755 · 음성 976.
- **누출(S4)**: 요약문에 `recall`이라는 글자가 들어 있는지만 보는 **키워드 한 줄이 민감도 0.793·특이도 0.882**를 낸다(`recall|campaign|573`이면 0.815·0.826). 현행 `FLAT_INV` 요약문은 조사가 끝난 뒤의 판본이라 결과가 새어 있다. 그대로 쓰면 "recall 글자 찾기"가 90% 재현율에 근접해 의미가 없어진다.
- **그래서 R2는 다음을 만족해야 유효하다**:
  1. 입력은 **조사 개시 시점 텍스트**(ODI Resume, 2007년 이후 개시분에서 확인된 PDF — 시점 평가가 이미 같은 방식으로 질문 판본을 옮김)만 쓴다. 결과를 알려 주는 단어·번호를 마스킹하는 것은 보조이고, 마스킹만으로는 부족하다.
  2. 시스템의 민감도가 **같은 특이도에서 키워드 기준선보다 유의하게 높아야** 한다(Wilson 구간이 겹치지 않을 것).
  3. 시간 분할: 개발 2010 미만, 검증 2010~2019, 시험 2020 이상. **시험 구간은 종결된 133건(양성 72·음성 61)뿐이라 구간이 넓다** — 민감도 0.90이 양성 72건이면 Wilson 95% 구간이 약 0.81~0.95다. 이 한계를 보고에 적는다.
- 라벨 잡음: "리콜 없이 종결 = 안전 결함 아님"이 아니다(제조사가 자발적으로 조치했거나 다른 이유로 종결). 정부 기록 기반 **대리 라벨**이라고 밝힌다.

## 5. R1(선례 증거) 설계 — 구체

**질문 고르기**(`pick_queries`, 검색을 보지 않는다): 차량 리콜(유형 V)·접수 2015-01-01 이후·결함 글 80~600자, 부품 대분류를 돌아가며 분류당 최대 3개, 시드 `20261016`. 이 규칙은 질문 글·카드 칸만 쓴다.
**후보 풀**(`build_pool`): 질문 리콜보다 먼저 접수·다른 중복 묶음인 카드 중 BM25·뜻 검색·RRF 각 상위 10(시스템 합집합, 중복 제거) + 통제 후보(같은 분류 5·다른 분류 3). 후보 번호는 해시라 순서·시스템을 추측할 수 없다.
**표시 값**: `2` 같은 부품이고 같은 고장 방식 / `1` 같은 부품이지만 다른 고장 / `0` 다른 부품. 후보 글(결함)만 보여 준다.
**표시 규칙**: 두 사람이 따로 표시하고 약 25%를 겹쳐 일치도(Cohen kappa)를 잰다. 합격선은 **kappa ≥ 0.6, 통제 후보(다른 분류)의 관련 표시 < 5%, 통제 후보(같은 분류)의 `2` 표시 < 15%** — 미달이면 그 표시자의 시트는 무효(S3). 합격선은 시험 전에 고정했고 결과를 보고 바꾸지 않는다.
**규모**: 40문항이면 후보 996줄이라 한 사람이 몇 시간 걸린다. **최소판 20문항(약 500줄)**을 권한다. 지금 만든 시트는 40문항(`r1_pool_sheet.csv`, 로컬)이고 앞 20문항만 써도 된다.
**점수**: Hit(상위 10에 `2`가 있는 질문의 비율, 문항 수·Wilson 구간), nDCG@10, 정밀도@10(`≥1`), 표시된 비율. **새 시스템**이 오면 상위 10 중 표시 안 된 후보만 추가 표시한다(S10).

## 6. "목표 재현율 90%" — 이 지표로 다시 정의 (D5 제안)

| 지표 | 제안 합격선 | 비고 |
|---|---|---|
| R1 Hit(상위 10) | **≥ 0.90** (유효 질문, 정밀도@10 ≥ 0.4 와 함께) | 정밀도 하한은 D5에서 정한다 — 제안값 |
| R2 민감도 | **≥ 0.90**, 특이도 ≥ 0.80에서, 키워드 기준선보다 유의하게 높음 | 특이도 하한은 D5에서 정한다 — 제안값 |
| E3 | 모든 자동 검사 100%·판정어 0건 | 재현율과 합치지 않는다 |

**평가를 쉽게 만들어 90%를 맞추지 않는다.** 이 설계에서 90%에 못 미치면 못 미친 대로 보고한다. 질문·후보·합격선은 결과를 보기 전에 고정하고(S7), 못 미치는 이유를 분석해 시스템을 고친다.

## 7. 이전 결과를 어떻게 다시 읽나

이슈 #128에 올린 탐색 시험 결과는 **현행 749문항 위의 숫자**라 다음처럼 읽는다.
- "사전·확장·어간 기각" → 이 평가셋으로는 효과를 판단할 수 없음(효과 없음이 증명된 것이 아님). E1로 다시 잰다.
- "jina-turbo H@3 +0.06" → 이 평가셋 위의 탐색값. 제품에서도 오르는지는 E1에서 확인한다.
- 리랭커 계획서 3절(사전 고정) 확정 전에 일부가 실행됐음은 별도로 밝힌 대로다.
