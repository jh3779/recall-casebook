## Agent Permissions

**자유롭게 한다**
- 파일 읽기, `git status`·`git log`·`git diff`, `uv run ruff check`·`ruff format --check`·`pytest`
- 문서·코드 수정 (요청 범위 안에서)
- (한시, ~2026-10-20, AGENTS.md 6-1) 담당 파트 밖 파일 수정 — 요청 범위 안이면 가능, PR 본문에 영향 파트를 적고 담당자에게 알린다(열람 제한 대상자는 제한 범위를 읽게 되는 수정·병합·리뷰에서 제외하고 `@태그`하지 않음 — AGENTS.md 6-1 1번 ④, 동시 수정 방지는 같은 1번 ③)
- (한시, ~2026-10-20, AGENTS.md 6-1 8번) 조사·테스트의 외부 근거 사용 — 새 조사·시험용 문서와 일회용 실험 스크립트만, 출처·"외부" 표시를 달고 서비스 경로는 제외 — 범위의 정본은 AGENTS.md 6-1 8번

**요청받았을 때만 한다** (AGENTS.md 6절)
- 커밋, push, PR 생성
  - (한시, ~2026-10-20, AGENTS.md 6-1) 그 세션을 연 팀원이 "진행"이라고 확인한 범위의 **작업 브랜치 커밋**(main·타인 소유 브랜치 제외)은 요청 없이 가능. push·PR 생성은 그대로 요청 시에만, main 커밋은 계속 금지, 이미 push한 커밋의 amend·rebase도 금지(DEC-035)
- 병합: 사용자가 그 PR의 병합을 명시적으로 지시하고 `MERGE_PROTOCOL.md` 게이트가 전부 ✅일 때만 `gh pr merge <N> --squash` (한시: 에이전트 병합은 우지훈이 그 세션에서 PR 번호를 들어 직접 지시한 경우만 — AGENTS.md 6-1 3번)
- force push: 요청 시에만 `--force-with-lease`

**먼저 묻고 확인받는다** (AGENTS.md 5·7절)
- 유료 API(LLM·임베딩) 대량 호출 — 예상 호출 수·비용을 먼저 말한다
- 전체 재색인·재임베딩 — 소량 표본 결과를 보여 준 뒤 진행한다
- 평가셋 변경(질문 추가·정답 표시)
- 서비스 원칙(2절)·되돌리기 어려운 결정 변경 — `DECISIONS.md`에 DEC로 남긴다

**하지 않는다**
- main 직접 커밋·push, `--no-verify`·`LEFTHOOK=0`으로 훅 우회
- `.env` 읽기·출력, 키·토큰 커밋
- 원본 데이터·벡터 인덱스 커밋, 실제 질문 원문의 저장소 반입
- 같은 컨텍스트에서 자기 작업을 "문제없음"으로 리뷰
