## Goal

## Tech Stack

- 확정: Python 3.12 + uv, 데이터 처리·기준선은 표준 라이브러리(BM25 직접 구현). 화면↔RAG 전달은 Python API 서버(DEC-038), 검색은 BM25 + 로컬 `bge-small-en-v1.5` RRF를 API 서버 메모리에서, 573 원인 칸이 있는 카드는 LLM 없이 원문을 보여 주고(DEC-039, 2026-10-09), 허용한 정리(쪽 머리말·꼬리말 제거·공백 정리)는 `text_basis`로 밝히며 NR·조사 중 서술은 `stated_unknown`으로 원문 보존(DEC-047). 카드 벡터는 Supabase pgvector가 정본이고 서버는 DB와 대조한 로컬 사본을 쓴다(DEC-042·044). 조사 요약 원인·573 꼬리표·확인 항목(DEC-044). 부품 범위 좁히기는 최상위 분류 순위 올리기를 기각(DEC-045). 공개 API는 Vercel 서버리스 위에서 비밀값 없는 호출 상한으로 지킨다(DEC-048·057) — 앱 상한(IPv4 주소별·IPv6 /64 묶음별 1분 60회, DEC-057 추가 결정)은 구현·배포됐고, Vercel WAF 안전망은 결정됐지만 규칙 설정과 실측은 사용자 계정 작업으로 남아 있다(설정 전, `docs/guides/배포_Vercel.md` 3-2절). 원인 칸 없는 카드의 화면 문구는 상태별 잠정 문구로 구현돼 있다 — 사용자가 보는 케이스북(영어 UI)은 `frontend/src/casebook/sources.ts`의 `causeLine()`·`causeBadge()`이고, `frontend/src/search/causeStatus.ts`(한국어)는 8D 화면의 "원문 없음 사유"(`eightd/evidenceText.ts`)에 쓰인다(DEC-047). 미정: 부품 트리 연결의 하위 분류 깊이·연결 실패 처리(할 일 22), 위 화면 문구의 사람 합의(대상은 케이스북 영어 문구와 8D 한국어 사유 문구 둘)·"원인 미확인" 표시 정확도(이슈 #53), 미보고 판별 경계("Pending" 등, 이슈 #83).

## Constraints

- 비밀키·토큰은 절대 커밋하지 않는다 (`.env`만 사용, lefthook pre-commit이 차단).
- main 직접 push 금지 — 단명 브랜치 → PR → squash merge (`CONTRIBUTING.md`).

## Agent Permissions

**자유롭게 한다**
- 파일 읽기, `git status`·`git log`·`git diff`, `uv run ruff check`·`ruff format --check`·`pytest`
- 문서·코드 수정 (요청 범위 안에서)

**요청받았을 때만 한다** (AGENTS.md 6절)
- 커밋, push, PR 생성
- 병합: 사용자가 그 PR의 병합을 명시적으로 지시하고 `MERGE_PROTOCOL.md` 게이트가 전부 ✅일 때만 `gh pr merge <N> --squash`
- force push: 요청 시에만 `--force-with-lease`

**먼저 묻고 확인받는다** (AGENTS.md 5·7절)
- 유료 API(LLM·임베딩) 대량 호출 — 예상 호출 수·비용을 먼저 말한다
- 전체 재색인·재임베딩 — 소량 표본 결과를 보여 준 뒤 진행한다
- 평가셋 변경(질문 추가·정답 표시)
- 서비스 원칙(2절)·되돌리기 어려운 결정 변경 — `DECISIONS.md`에 DEC로 남긴다

**하지 않는다**
- main 직접 커밋·push, `--no-verify`·`LEFTHOOK=0`으로 훅 우회
- `.env` 읽기·출력, 키·토큰 커밋
- 원본 데이터·벡터 인덱스 커밋, 실제 질문 원문의 저장소 반입
- 같은 컨텍스트에서 자기 작업을 "문제없음"으로 리뷰
