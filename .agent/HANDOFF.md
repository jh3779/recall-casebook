## Failed Attempts

- **커밋 제목이 영문 대문자로 시작해 lefthook 거부(세 번)**: 근본 원인은 규칙("첫 글자 대문자 금지")이 약어(`HANDOFF`·`FAQ`·`CI`)로 시작하는 제목에도 적용된다는 걸 놓친 것. 신호: 커밋 제목이 약어로 시작 → 한글 단어나 소문자로 시작하게 바꾼다. 거부된 줄 알아채지 못하고 `git push`가 이전 커밋만 올린 적도 있으니, 커밋 직후 `git log -1`로 실제 생성됐는지 확인한다.
- **이미 병합된 PR의 브랜치에 push**: 장시간 대기 뒤 push했더니 사용자가 웹에서 먼저 병합(#13)한 뒤였고 브랜치가 재생성됨. 신호: 대기가 길었거나 "병합 전 수정"을 약속한 PR → push 전에 `gh pr view <N> --json state`로 상태를 확인하고, 병합됐으면 최신 main 위 새 브랜치로 `cherry-pick`한다.
- **`.gitignore`에 `docs/handbook/*`가 없는 브랜치에서 `uv run ruff format .`**: ruff 0.15가 md 코드블록도 포맷해 로컬 데이터셋 8개가 바뀜(스크립트로 재다운로드해 복구). 신호: 데이터셋 폴더가 추적되지 않는 브랜치 → 경로를 지정해 포맷한다.

- **자동 리뷰의 반복 지적을 "근거 반박"으로만 대응하려 함**: "위험도 상"이 3번 반복됐는데 원인은 리뷰어의 낡은 로컬 `main`(첫 커밋)이었음. 신호: main에 없는 내용을 지적 → 먼저 `git show origin/main:<파일>`로 실제 줄을 확인하고, 그래도 반복되면 사용자에게 처리 방식을 묻는다.
- **PR #17에 push한 뒤 자동 리뷰 도착을 감시하지 않아 리뷰(`bdb90ea8`, 위험도 상 1·중 4)를 몇 시간 늦게 발견**: 근본 원인은 PR #15에서만 도착 감시를 걸고 #17은 push 후 다른 요청에 이어간 것. 신호: PR에 push했다 → 바로 `gh pr view <N> --json comments`로 새 head SHA 리뷰가 있는지 확인하거나 도착 감시(Monitor)를 건다.
